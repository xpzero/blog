注意力机制：模型怎样挑选上下文

2026年7月30日 · 阅读需 3 分钟

长提示词里放了很多资料，模型却可能抓错重点。注意力机制解释了它有能力参考哪些位置，但不保证它每次都会选对。理解这个边界，对写提示词和排查回答很有帮助。

注意力像一次带权检索​

处理某个词时，模型会向上下文提出一个“我需要什么”的查询，再根据各位置的匹配程度取回信息。常见资料把三部分叫 Query、Key、Value：查询、索引、内容。可以用下面的概念图记住：

当前词的需求 -> 给上下文各位置打分 -> 按分数混合它们的信息

“多头”表示同时进行几套打分和混合。不要把某个头硬解释为“专门看语法”：有时能观察到这种模式，但这不是模型给头分配的固定职责。

一个可以直接运行的加权例子​

下面代码展示权重如何改变结果。保存为 weighted_context.py 后执行 python weighted_context.py：

context = {"订单号": 1, "物流状态": 10, "优惠活动": 100}
weights = {"订单号": 0.3, "物流状态": 0.6, "优惠活动": 0.1}

result = sum(context[name] * weights[name] for name in context)
print(f"加权结果: {result}")
print("最受关注的位置:", max(weights, key=weights.get))

输出会指出“物流状态”权重最高。数字本身没有业务含义，重点是：权重高的位置对当前结果影响更大。真实模型在每一层、每一个词元上都重复这个过程，且值是高维向量，不是这里的单个数字。

两个实际规则​

生成式模型必须使用因果遮挡：正在生成“好”时只能看见此前文字，不能提前看见后面的答案，否则训练时等于作弊。

翻译或图文模型还会用交叉注意力：正在生成的一侧去参考另一侧输入。它和自注意力的区别只在于查询来自一边，而可参考的信息来自另一边。

长文本为什么麻烦​

普通注意力要比较许多位置对。文本变长时，这些比较和缓存都会增加，可能带来速度下降、显存不足或关键信息被淹没。局部注意力、稀疏注意力和分组查询是常见工程取舍，但具体支持情况取决于模型。

限制​

  • 查看注意力权重只能辅助调试，不能当作模型推理过程的完整解释。
  • 即使资料在上下文中，模型仍可能遗漏、误读或编造。
  • 更长的上下文窗口不是免费能力，需要同时验证成本、速度和回答质量。
