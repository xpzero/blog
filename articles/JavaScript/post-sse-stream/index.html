LLM 接口用 POST，前端怎么接收 SSE 流式响应？

柯寒2026年9月18日阅读 7 分钟

用 fetch 提交用户消息并读取 SSE 流式响应，附按文件整理的完整示例和启动方法。

前面写过 SSE 的基本使用，通过 new EventSource(url) 接收服务端推送。但 LLM 对话接口还需要用 POST 提交用户输入和对话历史，EventSource 却没有 method 和 body 参数。怎样提交消息，同时接收流式回答？

只能 GET 的是 EventSource​

原生 EventSource 只能发 GET，但 POST 的响应也可以使用 SSE 格式。 例如 OpenAI Chat Completions 接口通过 POST 接收 messages，设置 stream: true 后返回 SSE。

前端可以用 fetch 发出请求，再读取 response.body。下面是示例页面中的请求部分：

const response = await fetch("/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Accept: "text/event-stream",
  },
  body: JSON.stringify({ prompt: "你好" }),
});

请求的 Content-Type: application/json 描述发出去的数据；Accept 表达希望收到的格式。服务端则用响应头 Content-Type: text/event-stream 声明 SSE，并持续写入正文。

await fetch() 在响应头可用时就可以返回，正文通过 response.body 逐段读取。response.text() 和 response.json() 会等完整响应收齐，不适合边收边显示；整个 SSE 正文也不是一个 JSON 文档。

response.body 是 ReadableStream<Uint8Array>，其中每一块都是二进制字节。可以用 pipeThrough() 让它经过 TextDecoderStream，得到字符串流：

const textStream = response.body.pipeThrough(new TextDecoderStream());

TextDecoderStream 会持续按 UTF-8 解码。如果一个中文字符的字节被拆到两个数据块中，它会暂存不完整的字节并等待下一块，避免分别解码造成乱码。它只负责字符解码，不负责识别 SSE 事件边界，事件仍需通过后文的 buffer 拼接。

文件与启动方法​

示例用 Node 内置模块提供页面和 /chat，每 400ms 返回一段固定文本，没有调用真实 LLM。需要 Node.js，以及支持流式 fetch 和 TextDecoderStream 的现代浏览器，无需安装依赖。

在本地新建一个目录，把下面对应标签页中的代码保存为同名文件：

文件内容
server.mjs提供页面、接收 POST、发送 SSE
index.html发送请求、读取并显示增量、停止请求

在保存文件的目录运行：

node server.mjs

打开 http://127.0.0.1:9000，输入内容并点击“发送”，文字会分段出现；点击“停止”可中断请求，输入一个空格可观察 HTTP 400。终端按 Ctrl+C 停止服务。若提示 EADDRINUSE，修改服务端的监听端口，并访问对应地址。

解析范围：本例只处理单行 data: 、LF 换行和 \n\n 事件分隔符；数据为 {"delta":"新增文本"}，以 [DONE] 结束。其他 SSE 接口可能使用不同换行、多行数据或命名事件，需使用匹配其协议的解析器或 SDK。

server.mjs
import http from "node:http";
import { readFile } from "node:fs/promises";

const page = await readFile(new URL("./index.html", import.meta.url));

http.createServer(async (req, res) => {
  if (req.method === "GET" && req.url === "/") {
    res.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
    return res.end(page);
  }
  if (req.method !== "POST" || req.url !== "/chat") {
    return res.writeHead(404).end();
  }
  const requestType = req.headers["content-type"]
    ?.split(";")[0]
    .trim()
    .toLowerCase();
  if (requestType !== "application/json") {
    return res.writeHead(415).end();
  }

  let prompt;
  try {
    const chunks = [];
    let size = 0;
    for await (const chunk of req) {
      size += chunk.length;
      if (size > 4096) return res.writeHead(413).end();
      chunks.push(chunk);
    }
    ({ prompt } = JSON.parse(Buffer.concat(chunks).toString("utf8")));
    if (typeof prompt !== "string" || !prompt.trim() || prompt.length > 200) {
      return res.writeHead(400).end();
    }
  } catch {
    return res.writeHead(400).end();
  }

  res.writeHead(200, {
    "Content-Type": "text/event-stream; charset=utf-8",
    "Cache-Control": "no-store",
  });
  res.flushHeaders();
  const pieces = ["收到你的输入：", prompt, "\n这是本地分段返回的演示。"];
  const timer = setInterval(() => {
    if (!pieces.length) return res.end("data: [DONE]\n\n");
    res.write(`data: ${JSON.stringify({ delta: pieces.shift() })}\n\n`);
  }, 400);
  res.on("close", () => clearInterval(timer));
}).listen(9000, "127.0.0.1", () => {
  console.log("打开 http://127.0.0.1:9000");
});
index.html
<!doctype html>
<html lang="zh-CN">

  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>POST + SSE 本地演示</title>
  <style>
    :root { color-scheme: light dark; }
    body { max-width: 42rem; margin: 2rem auto; padding: 0 1rem; }
    textarea { display: block; box-sizing: border-box; width: 100%; }
    pre { white-space: pre-wrap; overflow-wrap: anywhere; }
  </style>
  <h1>POST + SSE 本地演示</h1>
  <p>服务端分段回显固定文本，没有调用 LLM。</p>
  <form id="form">
    <label for="prompt">用户输入</label>
    <textarea id="prompt" required maxlength="200">你好</textarea>
    <button id="send">发送</button>
    <button id="stop" type="button" disabled>停止</button>
  </form>
  <p id="status" role="status">等待发送</p>
  <pre id="output" aria-label="回答"></pre>

  <script type="module">
    const form = document.querySelector("#form");
    const prompt = document.querySelector("#prompt");
    const send = document.querySelector("#send");
    const stop = document.querySelector("#stop");
    const status = document.querySelector("#status");
    const output = document.querySelector("#output");
    let controller;

    stop.onclick = () => controller?.abort();
    form.onsubmit = async (event) => {
      event.preventDefault();
      if (controller) return;
      controller = new AbortController();
      send.disabled = true;
      stop.disabled = false;
      output.textContent = "";
      status.textContent = "接收中";
      try {
        const response = await fetch("/chat", {
          method: "POST",
          headers: {
            "Content-Type": "application/json",
            Accept: "text/event-stream",
          },
          body: JSON.stringify({ prompt: prompt.value }),
          signal: controller.signal,
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const type = response.headers
          .get("content-type")
          ?.split(";")[0]
          .trim()
          .toLowerCase();
        if (type !== "text/event-stream" || !response.body) {
          throw new Error("响应不是 SSE 流");
        }

        const reader = response.body
          .pipeThrough(new TextDecoderStream())
          .getReader();
        let buffer = "";
        try {
          while (true) {
            const { value: text, done } = await reader.read();
            if (done) break;

            const frames = (buffer + text).split("\n\n");
            buffer = frames.pop(); // 留下尚未结束的事件
            for (const frame of frames) {
              if (!frame.startsWith("data: ") || /[\r\n]/.test(frame)) {
                throw new Error("不支持的事件格式");
              }
              const data = frame.slice(6);
              if (data === "[DONE]") {
                status.textContent = "已完成";
                return;
              }
              const delta = JSON.parse(data)?.delta;
              if (typeof delta !== "string") throw new Error("缺少文本 delta");
              output.append(delta);
            }
          }
        } finally {
          reader.releaseLock();
        }
        throw new Error("未收到 [DONE]，回答可能不完整");
      } catch (error) {
        if (controller.signal.aborted) {
          status.textContent = "已停止";
        } else {
          status.textContent = `失败：${error.message}`;
        }
      } finally {
        controller.abort();
        controller = undefined;
        send.disabled = false;
        stop.disabled = true;
      }
    };
  </script>
</html>

读取时的三个要点​

  1. 一次读取不等于一条事件。 字节可能切在中文中间，也可能包含多条事件。TextDecoderStream 负责连续解码，buffer 负责保留未完整的事件，拼齐后才能 JSON.parse()。
  2. 流结束不等于回答完整。 先检查 HTTP 状态和响应类型；本例收到 [DONE] 才算完成，提前断流或解析失败会报错。[DONE] 是接口约定，不是 SSE 标准。
  3. 停止与重试要显式处理。 每次请求创建新的 AbortController，停止时调用 abort()。fetch 不会自动重连，重发 POST 可能重新生成并产生费用；后端还需要把取消传给上游模型服务。

接入真实 LLM 时，浏览器请求自己的业务后端，由后端保管服务商密钥并转换事件。按 Chat Completions 文档，文本增量在 choices[0].delta.content，并非每条事件都有文本；不能直接套用本例的 delta 字段。上游错误也要传给页面，已发出 200 响应头后，应通过约定的流内错误事件表达失败。

本例页面与接口同源。跨域接入需要配置 CORS；部署后若内容集中到最后出现，可参考流式输出与缓冲的区别。本地演示不代表真实模型或代理链路已验证。
