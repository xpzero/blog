Day 11 - 微调实战：数据准备与效果评估

2026年4月1日 · 阅读需 5 分钟

昨天了解了 LoRA、QLoRA 这些微调方法，今天想动手试试。但真到要跑训练的时候，发现数据准备比想象中麻烦。

数据格式长什么样​

微调需要的数据不是随便一段文本就行，得是特定格式。最常见的是 instruction-following 格式：

{
  "instruction": "把这句话翻译成中文",
  "input": "Hello, how are you?",
  "output": "你好，你好吗？"
}

或者是对话格式：

{
  "messages": [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！有什么可以帮助你的吗？"}
  ]
}

不同框架支持的格式不一样。Hugging Face 的 trl 库用第二种，LLaMA-Factory 两种都支持，但配置方式不同。

数据准备踩的坑​

坑1：数据量不是越大越好

一开始我以为数据越多越好，找了几十万条问答对。结果训练时发现训练时间太长，租的 GPU 按小时计费，而且数据质量参差不齐，模型学了很多噪声。

后来看论文发现，几千到几万条高质量数据，效果往往比几十万条低质量数据好。关键是数据要干净、多样、有代表性。

坑2：正负样本比例

做分类任务时，正负样本比例失衡会导致模型偏向多数类。我一开始没注意，结果模型预测全是"正面"，准确率虚高但没用。

解决方法：过采样少数类、欠采样多数类，或者直接用 Focal Loss。

坑3：数据泄露

训练集和测试集有重复，评估结果会虚高。我检查了一下自己的数据，发现确实有一些重复的问答对。去重之后，真实效果比评估低了 5-8 个点。

数据预处理流程​

现在我整理了一套预处理流程：

  1. 清洗：去重、去空、去异常长/短的样本
  2. 格式化：转换成模型需要的格式
  3. 切分：训练集 80%、验证集 10%、测试集 10%
  4. 检查：确保没有数据泄露，分布一致

用 Python 脚本处理：

import json
from sklearn.model_selection import train_test_split

# 加载数据
with open('raw_data.json', 'r') as f:
    data = [json.loads(line) for line in f]

# 去重
seen = set()
unique_data = []
for item in data:
    key = item['instruction'] + item['output']
    if key not in seen:
        seen.add(key)
        unique_data.append(item)

# 切分
train, temp = train_test_split(unique_data, test_size=0.2, random_state=42)
val, test = train_test_split(temp, test_size=0.5, random_state=42)

print(f"训练集: {len(train)}, 验证集: {len(val)}, 测试集: {len(test)}")

训练技巧​

学习率很重要

LoRA 的学习率一般设得比全参数微调小一个数量级。我试了几个值：

  • 1e-3：loss 震荡，不收敛
  • 1e-4：收敛正常
  • 1e-5：收敛太慢

最后选了 2e-4，配合 warmup 和 cosine decay。

早停（Early Stopping）

不要设死 epoch 数，看验证集 loss。连续 N 个 epoch 不下降就停，省时间还能防止过拟合。

from transformers import EarlyStoppingCallback

trainer = Trainer(
    ...,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)]
)

梯度累积

显存不够时，可以用梯度累积模拟大 batch size。比如 batch_size=4，accumulation_steps=4，实际等效 batch_size=16。

training_args = TrainingArguments(
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    ...
)

怎么评估微调效果​

这是个大问题。训练 loss 降了不代表模型变好。

自动评估

  • 困惑度（Perplexity）：越低越好，但只看这个不够
  • BLEU/ROUGE：和参考答案比 n-gram 重叠，适合翻译、摘要
  • Exact Match：问答任务看预测和答案是否完全一致

人工评估

自动指标有局限，最终还是得看人。我一般会从测试集随机抽 100 条，看模型输出和标准答案的差异，记录典型错误类型。

A/B 测试

同时保留原始模型和微调模型，让实际用户盲测哪个更好。这个最靠谱，但也最麻烦。

我现在的评估流程​

  1. 自动指标快速筛选（PPL、BLEU）
  2. 人工检查 100 条样本，看典型错误
  3. 和基座模型对比，确保没有灾难性遗忘
  4. 小范围上线，收集真实反馈

下一步​
