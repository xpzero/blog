pi 是一个跑在终端里的编码 Agent，TypeScript 写的。它为什么值得读源码：体量适中，但工程化程度高——会话持久化、上下文压缩、扩展系统、多种运行模式（交互 / print / JSON / RPC）都有完整实现；每个机制都能在自己机器上跑真实数据验证，不用靠猜。

这个系列按「旅程」组织：每篇文章走一条线，穿过同一张地图。

一张地图：四层​

pi 的仓库按包划分边界，正文里统一用下面这套称呼：

层对应的包职责
界面层tui 与 modes/interactive收集输入、渲染事件
编排层coding-agent 核心（AgentSession）加工消息、会话数据存取、压缩、树导航
循环层agent 包（Agent）循环推进一次运行：发请求、执行工具、发事件
协议层ai 包把请求翻译成各家厂商的 HTTP 协议

一句话记：下行靠调用，上行靠事件——去程是上层喊下层干活，回程是事件逐层向上广播。

另外有个会反复出现的角色：SessionManager（会话存储）。它物理上住在编排层的包里，系列第三篇会把它单独拉出来看，届时称「存储层」——那是职责视角，不是第五层。

术语表​

系列里的机制词统一按这张表使用：

术语含义
会话文件~/.pi/agent/sessions/ 下的 .jsonl 文件，一个会话一个文件
entry（条目）会话文件里的一行，记录一个事实
树全部 entry 依 id/parentId 连成的结构，事实的完整记录
转录（transcript）已提交消息的完整序列，树在活动分支上的切片
投影每次请求前从树推导「模型可见消息列表」的过程与结果
叶子（leafId）树上的当前节点指针，决定投影取哪条路径
内存消息数组agent.state.messages，转录的工作副本

一条权威链记住三者的关系：树 ⊇ 转录 ⊇ 投影结果，内存消息数组是投影的工作副本；不一致时以树（会话文件）为准——内存数组在每个请求前都会从树重新投影。
