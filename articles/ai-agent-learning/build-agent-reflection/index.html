抓住能抓住的：AI 辅助编程半年记

柯寒2026年9月13日阅读 5 分钟

从 opencode 入坑，到同时开五个六个 coding agent，再到被裁和重写 demo。半年 AI 辅助编程，心流成了奢侈品，把控感得自己拿回来。

这两年出了一个词儿，叫“古法编程”，对应着 vibe coding。尤其今年年初 openclaw 爆火，不管是不是 IT 行业的，都开始部署“小龙虾”：外行的可能出钱也要部署，内行的可能熬几个通宵去部署，热火朝天。各式各样的人开始 vibe coding，似乎程序员这个职业的壁垒一下就没了。

之后，各种概念频出，Prompt engineering、Context engineering、Harness engineering……。随着各厂商的LLM不断迭代升级，各公司老板、领导开始采取要求一定量的token消耗、AI使用率等措施，让开发人员使用AI辅助编程，“古法编程”的手搓似乎已经慢慢被抛弃了。可能是被迫，也可能是懒惰，却正在进行中。

我是今年1月底从opencode开始正式接触的AI辅助编程，为什么这么晚？一是公司没有给配AI软件，一是我用的neovim在终端中搭的开发环境，当时还不知道或者说还不认为AI做的很好，所以就一直没接入。直到刷到了和claude code差不多的opencode，因为是cli，和我的终端开发习惯很契合，就开始了。

使用AI的过程中，我从最开始的以为它神通广大，一句两句的要求它，到后面描述各种细节、条件的约束它，给它各种的上下文，差不多算是理解了，如何好好的使用它。

它从不理解我在说什么，开始慢慢的帮我实现代码，写出来我可能都不知道的官方api调用，再到帮我设计功能、走CI流程，而我只需要自然语言描述即可。

我不再完全的手写代码（毕竟上面要求AI使用率的），有需求了，基于脑子里对之前代码的熟悉程度，开始和AI一起设计代码架构、bug修复、功能上线。终端分屏，同时开5、6个coding agent，需求可以并行开发，而我的脑子也开始不停的“切换上下文”。不停的在多个coding agent之间确定修改的上下文，确认、提交。

慢慢的开始适应这种开发模式，不用手写，全靠自然语言，功能就实现了，真是解放双手了啊！可我发现我很难进入心流状态了，之前手搓代码的时候，一下午的时间很快就过去了。但是现在AI辅助之后，一直在不停的切换脑海中的上下文，心流成奢侈品了。

后来领导们开始要求需求量多起来、发版频次短起来，pd没有需求，开发需要自己想需求。再加上之前把测试部门撤了，问题开始出现了。一个是如果代码太多，review AI写的代码就是一件不切实际的事情，所以就会有不审代码直接发布的情况。另一个是，开发用开发思维去测功能，甚至有的开发是来帮忙的，前后业务逻辑也不会很了解，这样的话，bug率、严重性开始飙升。pd或者运营找到开发，开发说“AI写的，我也不知道”的情况。计算机系统里 CPU 切换上下文的消耗不小，人也差不多，开始心累，白头发疯长。

后来不心累了，被裁了……。

虽然用AI辅助编程的时间有半年了，但对于它的底层，比如agent如何连接LLM的原理，我是最近才开始看。原来除了LLM本身，其他基本和之前的软件开发差不多，页面显示、后端接口、逻辑处理，把上下文一并拼接给LLM，LLM计算回来之后，再拆分，再显示。也开始尝试写 agent 的 demo，刚开始我还会去找文档，一点点敲，后面我就直接让AI实现。直到后面想要写session管理的时候，各种逻辑判断、不认识的术语开始出现，但是AI还是一步步要我确认，而我就像个机器人一样不停的点Allow。

后面想，这不行，没有把控感，我得重写。真到重写的时候，环境构建要装各种工具包和起服务，让AI来吧，它比我快；切换LLM源，需要扒接入文档，好，我可以扒。后面接入不熟悉的技术，我要一个一个扒文档吗？来回切页面吗？NO，太浪费时间了，让AI来。“帮我连接LLM”、“帮我把前后端服务启起来”，“帮我写个联通前后端的demo“，……。AI似乎已经融入了我的开发习惯中，但是我为什么要重写呢？AI可以帮我实现一下费时费力的代码实现，但是逻辑我是要很具体的知道，它的流程是怎么走的，什么东西很重要，否则和一个全新的小白没区别。

网上关于 AI 的讨论很多：未来不需要程序员了、警惕AI陷阱、LLM 厂商在延缓升级进度、AI 造成了更大的代码“屎山”……。

言论很多，而我活在当下，抓住能抓住的一切，无疚即可。
