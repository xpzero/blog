给 pi 装一块仪表盘：让生命周期事件在终端里滚起来

前文数清了 pi 的生命周期：四层嵌套，几十个事件。百闻不如一见。这篇给 pi 装一块仪表盘：编辑器下方一块固定高度的日志面板，让这些事件在真实运行里滚过终端。装好之后，一次普通运行的结尾长这样：

00:50:32 tool read done (9ms)
00:50:32 turn end (1 tool results)
00:50:32 turn start
00:50:39 assistant streaming
00:50:40 assistant done (in 371, out 119)
00:50:40 turn end
00:50:40 loop end
00:50:40 settled

一行一件事：工具收工、回合闭合、新回合开启、模型开始流式、消息定稿、回合再闭合。最后两行是重点——loop end 与 settled，一个是循环层收工，一个是编排层放行，为什么是两行、中间隔着什么，实测一节对账。

层名沿用同一套叫法，从外到里：会话、运行、回合、消息、工具调用。事件体系的全貌推导见前文：数一数 pi 的生命周期：到底有多少事件，多少层。

信息

本文源码核对自 earendil-works/pi 仓库 commit 8efd314f。面板扩展约 260 行 TypeScript，全文见下节折叠区；两段实测截图来自真实 pi 会话。

扩展长什么样​

pi 的扩展就是一个 TypeScript 文件，放进 ~/.pi/agent/extensions/，启动时自动加载。对文件只有一个要求：默认导出一个工厂函数。pi 加载时调用它一次，传入 API 对象：

export default function lifecycleLogExtension(pi: ExtensionAPI) {
	// 所有能力都从这个 pi 对象上拿
}

这块仪表盘用到四个能力：

  • pi.on(event, handler)：订阅生命周期事件，本文的主角；
  • pi.registerCommand(name, options)：注册斜杠命令——/lifecycle-log 开关面板，/lifecycle-log clear 清空日志；
  • ctx.ui.setWidget(key, factory, options)：把一个渲染组件挂进输入区；
  • ctx.hasUI：运行模式守卫，print 和 JSON 模式没有界面，挂面板前先查。

工厂函数体里只放数据和纯函数，面板组件在 session_start 事件里创建。原因：有些调用只加载扩展不启动会话，工厂函数里建的界面组件没有归宿。这条规矩对所有扩展生效——组件和长活资源从会话开始处开、结束处关。

一条设计决定贯穿全文：日志数据放在扩展闭包的 entries 数组里，面板只是它的一个视图。面板被关掉再打开，日志一条不丢；没有界面时事件照记，账一直在。

/**
 * Lifecycle log panel.
 *
 * Renders a fixed-height log panel below the editor that records agent-loop
 * lifecycle events as they happen: session start/shutdown, loop start with the
 * prompt, turn start/end, message start/end, tool execution start/end with
 * duration, loop end, and settled.
 *
 * The panel follows the newest entry. Hover it and scroll with the mouse wheel
 * to inspect history; scrolling back to the bottom resumes following. The
 * keyboard is intentionally untouched: the editor keeps focus.
 *
 * The widget is a hand-driven viewport instead of a pi-tui ScrollView because
 * extension widgets are rendered inside a plain Container in the input dock:
 * the layout engine treats that container as a leaf, so nested ScrollViews get
 * no layout wiring (no updateLayout, no wheel routing). The panel therefore
 * implements scrolling itself: render() slices entries by scrollTop and draws
 * a scrollbar column, handleMouse() consumes wheel events.
 *
 * Usage:
 *   /lifecycle-log        toggle the panel
 *   /lifecycle-log clear  clear the log
 */

import type { ExtensionAPI, Theme, ThemeColor } from "@earendil-works/pi-coding-agent";
import { type Component, type TuiMouseEvent, type TuiMouseEventResult, truncateToWidth } from "@earendil-works/pi-tui";

const WIDGET_KEY = "lifecycle-log";
const PANEL_HEIGHT = 8;
const MAX_ENTRIES = 500;

interface LogEntry {
	time: string;
	text: string;
	color: ThemeColor;
}

function timestamp(): string {
	const now = new Date();
	const pad = (n: number) => String(n).padStart(2, "0");
	return `${pad(now.getHours())}:${pad(now.getMinutes())}:${pad(now.getSeconds())}`;
}

function preview(text: string, maxLength = 60): string {
	const single = text.replace(/\s+/g, " ").trim();
	return single.length > maxLength ? `${single.slice(0, maxLength)}...` : single;
}

/** Compact single-line summary of tool arguments, truncated to fit a log row. */
function formatArgs(args: unknown, maxLength = 80): string {
	if (args === undefined || args === null) return "";
	let text: string;
	if (typeof args === "string") text = args;
	else {
		try {
			text = JSON.stringify(args) ?? String(args);
		} catch {
			text = String(args);
		}
	}
	text = preview(text, maxLength);
	return text ? ` ${text}` : "";
}

class LifecycleLogPanel {
	private scrollTop = 0;
	private following = true;
	private readonly entries: LogEntry[];
	private readonly theme: Theme;
	private readonly requestRender: () => void;

	constructor(entries: LogEntry[], theme: Theme, requestRender: () => void) {
		this.entries = entries;
		this.theme = theme;
		this.requestRender = requestRender;
	}

	private get maxScrollTop(): number {
		return Math.max(0, this.entries.length - PANEL_HEIGHT);
	}

	append(entry: LogEntry): void {
		this.entries.push(entry);
		if (this.entries.length > MAX_ENTRIES) this.entries.splice(0, this.entries.length - MAX_ENTRIES);
		if (this.following) this.scrollTop = this.maxScrollTop;
		this.requestRender();
	}

	reset(): void {
		this.entries.length = 0;
		this.scrollTop = 0;
		this.following = true;
		this.requestRender();
	}

	private scrollBy(lines: number): void {
		const next = Math.max(0, Math.min(this.maxScrollTop, this.scrollTop + lines));
		if (next === this.scrollTop) return;
		this.scrollTop = next;
		this.following = this.scrollTop === this.maxScrollTop;
		this.requestRender();
	}

	handleMouse(event: TuiMouseEvent): TuiMouseEventResult | undefined {
		if (event.type !== "wheel") return undefined;
		this.scrollBy(-(event.wheelDelta ?? 0));
		return { handled: true };
	}

	invalidate(): void {}

	render(width: number): string[] {
		const theme = this.theme;
		const header = theme.fg("muted", ` lifecycle log (${this.entries.length})`);
		const lines = [truncateToWidth(header, width, "", true)];

		const bodyWidth = Math.max(0, width - 1); // reserve scrollbar column
		const scrollable = this.entries.length > PANEL_HEIGHT;

		for (let row = 0; row < PANEL_HEIGHT; row++) {
			const entry = this.entries[this.scrollTop + row];
			if (entry === undefined) {
				lines.push(" ".repeat(width));
				continue;
			}
			const time = theme.fg("dim", entry.time);
			const text = theme.fg(entry.color, entry.text);
			lines.push(truncateToWidth(`${time} ${text}`, bodyWidth, "", true));
		}

		for (let row = 0; row < PANEL_HEIGHT; row++) {
			let column = " ";
			if (scrollable) {
				const thumbSize = Math.max(1, Math.round((PANEL_HEIGHT / this.entries.length) * PANEL_HEIGHT));
				const thumbTop =
					this.maxScrollTop === 0
						? 0
						: Math.round((this.scrollTop / this.maxScrollTop) * (PANEL_HEIGHT - thumbSize));
				const isThumb = row >= thumbTop && row < thumbTop + thumbSize;
				column = isThumb ? theme.fg("scrollbarThumb", "█") : theme.fg("scrollbarTrack", "│");
			}
			lines[row + 1] += column;
		}

		return lines;
	}
}

export default function lifecycleLogExtension(pi: ExtensionAPI) {
	const entries: LogEntry[] = [];
	let visible = true;
	let panel: LifecycleLogPanel | undefined;

	function log(text: string, color: ThemeColor = "text"): void {
		const entry = { time: timestamp(), text, color };
		if (panel) panel.append(entry);
		else {
			entries.push(entry);
			if (entries.length > MAX_ENTRIES) entries.splice(0, entries.length - MAX_ENTRIES);
		}
	}

	function createPanel(tui: { requestRender(): void }, theme: Theme): Component & { dispose(): void } {
		const next = new LifecycleLogPanel(entries, theme, () => tui.requestRender());
		panel = next;
		return {
			render: (width: number) => next.render(width),
			invalidate: () => next.invalidate(),
			handleMouse: (mouseEvent: TuiMouseEvent) => next.handleMouse(mouseEvent),
			dispose: () => {
				if (panel === next) panel = undefined;
			},
		};
	}

	// ---- 会话层 ----

	pi.on("session_start", (event, ctx) => {
		log(`session ${event.reason}`, "muted");
		if (!ctx.hasUI || !visible) return;
		ctx.ui.setWidget(WIDGET_KEY, (tui, theme) => createPanel(tui, theme), { placement: "belowEditor" });
	});

	pi.on("session_shutdown", (event) => {
		log(`session shutdown (${event.reason})`, "muted");
	});

	// ---- 运行层 ----

	pi.on("before_agent_start", (event) => {
		log(event.messageType === "user" ? `loop start: ${preview(event.prompt)}` : "loop start", "accent");
	});

	pi.on("agent_end", () => {
		log("loop end", "muted");
	});

	pi.on("agent_settled", (event) => {
		log(event.aborted ? "settled (aborted)" : "settled", "success");
	});

	// ---- 回合层 ----

	pi.on("turn_start", () => {
		log("turn start", "muted");
	});

	pi.on("turn_end", (event) => {
		log(
			event.toolResults.length > 0 ? `turn end (${event.toolResults.length} tool results)` : "turn end",
			"muted",
		);
	});

	// ---- 消息层 ----

	pi.on("message_start", (event) => {
		if (event.message.role === "assistant") log("assistant streaming", "dim");
	});

	pi.on("message_end", (event) => {
		if (event.message.role === "assistant") {
			log(`assistant done (in ${event.message.usage.input}, out ${event.message.usage.output})`, "dim");
		}
	});

	// ---- 工具层 ----

	pi.on("tool_execution_start", (event) => {
		log(`tool ${event.toolName} start${formatArgs(event.args)}`, "accent");
	});

	pi.on("tool_execution_end", (event) => {
		if (event.isError) log(`tool ${event.toolName} failed`, "error");
		else {
			const duration = event.durationMs !== undefined ? ` (${event.durationMs}ms)` : "";
			log(`tool ${event.toolName} done${duration}`, "success");
		}
	});

	// ---- 面板命令 ----

	pi.registerCommand("lifecycle-log", {
		description: "Toggle the lifecycle log panel (args: clear)",
		handler: async (args, ctx) => {
			if (args.trim() === "clear") {
				entries.length = 0;
				panel?.reset();
				ctx.ui.notify("Lifecycle log cleared", "info");
				return;
			}
			visible = !visible;
			if (!ctx.hasUI) return;
			if (visible) {
				ctx.ui.setWidget(WIDGET_KEY, (tui, theme) => createPanel(tui, theme), { placement: "belowEditor" });
				ctx.ui.notify("Lifecycle log shown", "info");
			} else {
				ctx.ui.setWidget(WIDGET_KEY, undefined);
				ctx.ui.notify("Lifecycle log hidden", "info");
			}
		},
	});
}

订阅哪些事件​

订阅按五层分组，每层挑能回答"它现在在干什么"的事件：

层订阅面板记下的行
会话session_start、session_shutdownsession startup、session shutdown (reason)
运行before_agent_start、agent_end、agent_settledloop start: <prompt 预览>、loop end、settled
回合turn_start、turn_endturn start、turn end (N tool results)
消息message_start、message_endassistant streaming、assistant done (in X, out Y)
工具tool_execution_start、tool_execution_endtool read start …、tool read done (9ms)、tool bash failed

五个取舍：

  • 运行层的开始订阅 before_agent_start：它带着触发这次运行的 prompt，日志行能自己说话，预览截 60 字；
  • 消息层只记 assistant：其余角色的消息整条出现、整条定稿，起止两行没有信息量；assistant 是唯一"长出来的"，起止之间是流式过程；
  • 消息定稿带上 token 账：usage.input 与 usage.output 由 message_end 事件自带，一条消息一笔账；
  • 工具的结束分两支：失败记 tool bash failed，成功带耗时 tool read done (9ms)，durationMs 也是事件自带的；
  • 回合结束带上 toolResults.length：一个回合产出几条工具结果，一眼可见。

订阅代码本身很直白，挑两处看。运行层的开始：

pi.on("before_agent_start", (event) => {
	log(event.messageType === "user" ? `loop start: ${preview(event.prompt)}` : "loop start", "accent");
});

工具的结束：

pi.on("tool_execution_end", (event) => {
	if (event.isError) log(`tool ${event.toolName} failed`, "error");
	else {
		const duration = event.durationMs !== undefined ? ` (${event.durationMs}ms)` : "";
		log(`tool ${event.toolName} done${duration}`, "success");
	}
});

面板怎么活：放置、渲染与滚动​

先说能放在哪。setWidget 的 placement 只有两个合法值：aboveEditor 和 belowEditor。两个都是输入停靠区里的全宽横条，区别只是位于编辑器上方还是下方——pi 的终端布局是纯纵向的（上面对话流、下面输入区），没有侧栏，"放在右边"不在协议里。这块面板选 belowEditor：不占编辑器上方的空间，宽度全额可用。

渲染走一套极简协议：组件实现 render(width)，返回一行一个元素的字符串数组；高度自己负责，面板固定 8 行。数据侧每 append 一条，就调一次 requestRender() 请求宿主重绘。键盘刻意不碰——编辑器保持焦点；滚轮走 handleMouse。

滚动是手写的，没用现成的 ScrollView。原因在扩展的源码注释里就写着：扩展 widget 渲染在输入停靠区的一个普通 Container 里，布局引擎把这个容器当叶子节点，嵌套的 ScrollView 拿不到 updateLayout 接线，也收不到滚轮路由。于是面板自己实现视口，三件事：

  • render() 按 scrollTop 切片，只画可见的 8 行；
  • handleMouse() 消费滚轮事件，换算成 scrollTop 增减；
  • 最右一列手画滚动条，拇指的大小和位置按可见行数占比算出。

跟随模式：新日志到来时 scrollTop 钉在底部；用户往上滚就暂停跟随，翻回底部自动恢复。日志上限 500 条，超了从头丢弃。

实测：两段真实会话​

环境交代：扩展常驻 ~/.pi/agent/extensions/；两段任务都在 pi 仓库根目录发起；截图取自终端，未做修饰。

一段完整运行​

任务本身带点自指：让 pi 数一数 packages 下有多少个子目录，再读 agent 包里 AgentEvent 的定义。于是面板在记录 pi 的生命周期，而 pi 在读自己的事件定义。

面板共 21 条，截图露出末 8 行。按时间线对账：

  • 任务发起：loop start 带出 prompt 预览。滚出视野的前 13 条覆盖了前两个回合——首回合模型并行发起两个 bash（各 20 毫秒上下），第二回合一次 read，读的正是 types.ts；
  • tool read done (9ms)：read 收工，耗时 9 毫秒，事件自带；
  • turn end (1 tool results)：第二回合闭合，产出一的工具结果；
  • turn start → assistant streaming：第三回合开启。注意时间——回合 32 秒就开了，流式 39 秒才开始，中间 7 秒花在等首个响应帧，面板如实记下；
  • assistant done (in 371, out 119)：模型不再调工具，流式给出最终答复，371 进 119 出，这条消息的 token 账记在日志行上；
  • turn end → loop end：回合闭合，没有待执行的工具、没有排队的消息，循环层收工；
  • settled：编排层把重试判断、压缩检查这些收尾做完，广播安静信号。它与 loop end 同秒先后落地——间隔可以很短，但它们是两个事件：一个说"模型不再转了"，一个说"pi 整体安静了"。输入区的忙碌指示器，多转的那段时间就落在这两行之间。

一次 Esc 中止​

换一个任务：列出每个包的 name 字段。趁模型流式时按 Esc。

面板已记到第 61 条——同一会话里此前的几轮运行都在账上。末 8 行对账：

  • tool bash done (502ms) → turn end (1 tool results)：工具收工、回合闭合，这些发生在 Esc 之前；
  • turn start → assistant streaming：新回合开启，模型开始流式；
  • assistant done (in 0, out 0)：Esc 落在这里。正在生长的消息以空账定稿，0 进 0 出，停止原因记为 aborted；
  • turn end → loop end → settled (aborted)：回合、运行逐层用正常仪式宣布结束，settled 带上 aborted 标记，与正常收尾区分开。

中止不是把事件流掐断，而是让每一层把仪式走完。面板上没有一条日志凭空消失，也没有一条凭空出现。

Esc 落在工具执行中时会怎样？中止信号会传进工具的 execute()：bash 收到后杀掉自己起的整个进程树，再以错误返回；循环层不丢下已开跑的调用，等它 settle、补完 tool_execution_end，批次里还没开始的调用直接以 aborted 结果收场。循环层递信号，工具自己收场——仪式一个不少。

结语​

这块仪表盘的全部家当：一份订阅清单，一个渲染组件，两百多行胶水。事件协议在先，订阅即得——界面、落盘、扩展拿到的是同一套广播。

面板从头到尾只做一件事：看。不改消息，不拦工具，不注内容。
