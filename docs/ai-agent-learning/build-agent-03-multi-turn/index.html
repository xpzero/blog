从零手写 Agent（三）：为什么它记不住上一句话

前两篇的程序有个很别扭的地方：每次运行只能问一句话，问完就退出。改成循环让它连着问，会发现更奇怪的现象——

你: 北京天气怎么样
Agent: 北京今天晴，最高气温 38℃。
你: 那上海呢
Agent: 请问您想了解上海的什么信息？

它不知道「那上海呢」是在问天气。这不是模型笨，而是我们根本没把上一轮的内容告给它。

根因：Chat Completions 接口是无状态的​

第一篇提过这件事，这里要用上了：模型能看到的全部信息，只有你这次请求传进去的 messages。

前两篇的代码每次都新建 messages：

def run_agent(user_input: str, max_turns: int = 10):
    messages = [                          # 每次调用都是全新的列表
        {"role": "system", "content": "..."},
        {"role": "user", "content": user_input},
    ]

所以第二次提问时，历史消息压根不存在。所谓「上下文」不是模型内部的状态，就是这个列表。

修复方式简单到有点反直觉：把 messages 从函数内部挪出来，整个会话复用同一份。

双层循环​

改完之后代码结构变成两层，这是本篇的重点。

为什么需要两层？因为工具调用打破了「一次用户输入 = 一次模型请求」的对应关系。

没有工具时，一层就够：读输入、请求、打印，一句对一句。有了工具之后，用户说一句话，程序内部可能要跟模型往返三四次（第二篇那个自循环）才能得出答案。这两件事的节奏不同，只能分开：

外层 while：读用户输入 → 追加 user 消息 → 进内层
内层 for  ：agent loop（同第二篇），直到模型给出文本回复 → 回外层等下一句

两层各管一件事：

层一次迭代 =本 demo 的结束条件
外层一次用户输入用户输入 quit
内层一次模型请求模型不再返回 tool_calls

这张表写的是本 demo 的做法。内层用「模型不再要求调工具」来判断结束，是最简单可行的方案；真实项目还要处理回复被截断、预算耗尽、用户中断等情况，第二篇末尾列过。

max_turns 没有出现在表里——它是我们自己加在内层的保护上限，不属于协议，模型也感知不到，只是防止模型一直要求调工具导致循环停不下来。

代码​

内层就是第二篇的循环，原样搬过来抽成函数：

def run_tool_loop(messages: list, max_turns: int = 10) -> None:
    """反复请求模型并执行工具，直到模型给出最终文本回复。messages 会被原地追加"""
    for _ in range(max_turns):
        response = client.chat.completions.create(
            model=MODEL, messages=messages, tools=TOOLS
        )
        message = response.choices[0].message
        messages.append(message)

        if not message.tool_calls:
            print(f"Agent: {message.content}")
            return

        # 执行工具、把结果以 role="tool" 追加进 messages（同第二篇）
        ...

外层负责收输入：

def chat() -> None:
    # 关键：messages 在循环外，整个会话共用一份
    messages = [{"role": "system", "content": SYSTEM_PROMPT}]

    print("Agent 已启动，输入 quit 退出")

    while True:
        user_input = input("你: ")
        if user_input.strip().lower() in ("quit", "exit", "q"):
            break

        messages.append({"role": "user", "content": user_input})
        run_tool_loop(messages)

input().strip() 去掉首尾空白，避免用户多打一个空格导致退出指令判断失败。

一个容易犯的错：只保留最终回复​

有人会想：工具调用那些中间消息看着挺乱，只把模型最后那句文本留在上下文里不行吗？

不行。assistant 和 tool 消息都必须留下。原因有两个：

  1. 协议层面，role="tool" 的消息必须能通过 tool_call_id 找到对应的 assistant 消息。删掉前者，下一次 create() 就会被模型服务端拒掉（400 No tool output found for function call ...）
  2. 模型层面，删掉之后它就不知道自己查过什么了。下一轮你问「刚才查的温度再算一下」，它只能重新查一遍

效果​

$ uv run main.py
Agent 已启动，输入 quit 退出
你: 北京天气怎么样
  [工具调用] get_weather({'city': '北京'})
  [返回结果] 北京今天晴，最高气温38℃
Agent: 北京今天晴，最高气温 38℃，天气炎热，外出请注意防暑降温。
你: quit

现在接着追问「那上海呢」，模型能从上下文推断出你还在问天气。

代价：上下文只会变长​

这个方案有个必然的副作用——messages 单向增长，永远不会变短。聊得久了会超出模型的上下文长度限制。

真实产品需要做上下文管理：超长时裁剪旧消息、或者把早期对话压缩成摘要。这是一个真实存在的天花板。
