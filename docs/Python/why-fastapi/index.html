FastAPI 是什么：从一个简单 Demo 开始

最近我在了解一个很基础的问题：如果想用 Python 写后端，应该怎么实现？

查资料时，我看到了 FastAPI。但刚看到这个名字时，我并不清楚它到底是什么：它是一个服务器，还是一个 Python 库？为什么写几行代码，就能得到一个可以访问的接口？

FastAPI 是什么​

FastAPI 是一个用 Python 构建 Web API 的框架。这里的“框架”可以先理解为一套组织后端程序的规则和工具：按照它的方式声明路径和函数，它负责把 HTTP 请求交给对应的代码处理。

这里的 API，可以先简单理解为后端对外提供的访问入口。客户端向一个 URL 发送 HTTP 请求，后端接收请求、执行 Python 代码，再把结果返回给客户端。例如：

GET /users/7

这个请求可以理解为“获取编号为 7 的用户”。后端处理完成后，可能返回一段 JSON 数据：

{
  "user_id": 7
}

如果完全从底层处理，我需要自己识别 URL、判断请求方法、读取参数、检查数据，再组织 HTTP 响应。FastAPI 把这些常见工作封装了起来，让我可以把注意力先放在 Python 函数和业务逻辑上。

FastAPI 可以作为 Python 包安装。写好应用后，运行 fastapi dev 就会启动本地开发服务器，浏览器或其他客户端随后可以向它发送请求。

本次实测环境

以下命令于 2026-08-29 在本机实际运行：uv 0.11.32、Python 3.12.13、FastAPI 0.141.1、Pydantic 2.13.5。本文只记录这个环境中实际观察到的结果。

第一步：创建项目​

这里使用 uv 管理 Python 版本、项目和依赖。先创建一个名为 fastapi-demo 的目录，并安装 FastAPI：

uv init --python 3.12 fastapi-demo --bare
cd fastapi-demo
uv add "fastapi[standard]==0.141.1"

这几条命令做了三件事：

  • uv init 创建 Python 项目，并让 uv 选择 Python 3.12；
  • uv add 把 FastAPI 写入项目依赖；
  • [standard] 同时安装运行开发服务器所需的常用依赖。

安装完成后，项目中会有 pyproject.toml 和 uv.lock。前者记录项目依赖，后者记录这次实际解析出的依赖版本。

可以直接检查实际安装的版本：

uv run python -c 'import fastapi, pydantic; print(f"FastAPI {fastapi.__version__}"); print(f"Pydantic {pydantic.__version__}")'

本次输出是：

FastAPI 0.141.1
Pydantic 2.13.5

FastAPI 0.141.1 要求 Python 3.10 或更高版本。本次终端中的 python3 --version 显示为 3.9.6，不满足这个要求，所以创建项目时显式选择了 Python 3.12。根据 uv 的 Python 版本文档，uv 会优先寻找合适的解释器，默认情况下，找不到需要的版本时会自动下载。

第二步：写一个最小接口​

在项目根目录新建 main.py：

from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def hello():
    return {"message": "Hello FastAPI"}

然后启动开发服务器：

uv run fastapi dev main.py

这个命令默认使用 8000 端口。本次运行时，终端返回了：

[Errno 48] Address already in use

本机已经有另一个开发服务占用了 8000 端口。我没有停止原有服务，而是给当前 Demo 换成 8001：

uv run fastapi dev main.py --port 8001

这次服务正常启动，终端给出了两个地址：

Server started at http://127.0.0.1:8001
Documentation at http://127.0.0.1:8001/docs

如果本机的 8000 端口没有被占用，可以继续使用默认端口；后面的请求使用本次实测的 8001。验证结束后，在运行服务器的终端按 Ctrl+C 即可停止服务。

另开一个终端发送请求：

curl http://127.0.0.1:8001/

实际响应是：

{"message":"Hello FastAPI"}

到这里，一个最小的后端接口已经可以访问了。

这几行代码做了什么​

先逐行看一下：

  • app = FastAPI() 创建一个 FastAPI 应用；
  • @app.get("/") 表示接收路径为 / 的 GET 请求；
  • hello() 是收到这个请求后要执行的 Python 函数；
  • 函数返回一个字典，FastAPI 把它转换成 JSON 响应。

这里最关键的是 @app.get("/")。它把“GET 请求的 / 路径”和 hello() 函数连接了起来，这种对应关系叫作路由。

第三步：接收路径参数​

只有固定的 / 还看不出参数是怎么传进 Python 函数的。继续在 main.py 末尾增加一个接口：

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}

开发服务器会自动重新加载代码。访问一个具体的用户编号：

curl http://127.0.0.1:8001/users/7

实际响应是：

{"user_id":7}

{user_id} 表示 URL 中这一段是可变的。请求 /users/7 时，FastAPI 取出 7，再把它传给 get_user() 的 user_id 参数。

函数参数还写了 user_id: int。为了观察这个类型标注是否真的起作用，可以故意传入一个不能转换成整数的值：

curl -i http://127.0.0.1:8001/users/abc

实际状态码是 422。省略日期等响应头后，响应中的关键信息是：

HTTP/1.1 422 Unprocessable Entity
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["path", "user_id"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "abc"
    }
  ]
}

422 是一个 HTTP 状态码，表示请求格式可以被服务读取，但其中的数据不符合接口声明的要求。这里的 loc 指向路径中的 user_id，说明错误发生在这个参数上。

再确认一下：是 Python 自己在校验吗​

这里容易产生一个误解：是不是只要 Python 参数写了 int，它就会自动检查类型？

单独运行下面这段普通 Python 代码：

def keep(value: int) -> int:
    return value


result = keep("42")
print(result, type(result).__name__)

本次实际输出是：

42 str

这说明 Python 的类型标注本身没有把字符串转换成整数，也没有阻止这次调用。前面的接口之所以会校验 user_id，是因为 FastAPI 读取了函数参数的类型标注，并根据它处理请求数据。

第四步：接收 JSON 请求体​

路径参数适合传递用户编号。如果要创建一个用户，通常还需要接收姓名、年龄等数据。这些数据可以放在 HTTP 请求体中，以 JSON 格式发送。

把 main.py 更新为：

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UserCreate(BaseModel):
    name: str
    age: int


@app.get("/")
def hello():
    return {"message": "Hello FastAPI"}


@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}


@app.post("/users")
def create_user(user: UserCreate):
    return {"name": user.name, "age": user.age}

Pydantic 在这里是什么​

Pydantic 是一个使用 Python 类型标注处理数据的库。它可以描述数据结构、转换输入并检查输入是否符合要求。安装 FastAPI 时，它已经作为依赖一起安装，不需要在这个项目中单独添加。

UserCreate 继承了 Pydantic 的 BaseModel，Pydantic 会把它作为数据模型处理：

  • name: str 声明 name 字段最终应该是字符串；
  • age: int 声明 age 字段最终应该是整数；
  • 两个字段都没有默认值，所以请求中缺少任何一个都会校验失败。

UserCreate 不是数据库表，也不会保存用户。它只描述进入 create_user() 之前，这份数据应该具有怎样的结构。

当 FastAPI 看到函数参数 user: UserCreate 时，会把它识别为请求体模型。根据 FastAPI 的请求体文档，处理过程可以简化为：

请求中的 JSON → FastAPI 读取请求体 → Pydantic 转换、校验并创建对象 → UserCreate 对象 → create_user()

这里的“校验”，是指 Pydantic 根据 UserCreate 中已经声明的规则检查输入：必填字段是否存在、字段值能否符合对应类型，以及是否满足额外声明的限制。这个模型只声明了字段类型，没有声明年龄必须大于 0 等业务限制。

校验不只是比较输入原本是什么类型。Pydantic 有时会先尝试转换输入，例如把字符串 "18" 转换成整数 18。如果处理成功，它会创建 UserCreate 对象；如果处理失败，它会产生校验错误，再由 FastAPI 把错误转换成 422 响应。

接着发送一个 POST 请求：

curl -X POST http://127.0.0.1:8001/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"小明","age":18}'

实际响应是：

{"name":"小明","age":18}
补充：Pydantic 如何处理不同的 age 输入

为了观察类型转换和校验的边界，把年龄改成不能转换成整数的文字：

curl -i -X POST http://127.0.0.1:8001/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"小明","age":"十八"}'

实际状态码是 422，响应中的 loc 指向请求体里的 age：

{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["body", "age"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "十八"
    }
  ]
}

把前后的请求结果放在一起比较：

JSON 中的 age实际状态码实际结果
18200返回整数 18
"18"200字符串被转换成整数 18
"十八"422无法转换成整数
-1200返回整数 -1

这组结果说明，Pydantic 会按照模型尝试转换和校验输入，但只覆盖已经声明的规则。age: int 没有规定年龄必须大于 0，因此 -1 仍然通过了校验。数据在业务上是否合理，还需要继续声明限制或编写业务代码判断。

第五步：查看自动生成的接口文档​

保持服务运行，在浏览器中打开：

http://127.0.0.1:8001/docs

/docs 是一个基于 Swagger UI 的交互式接口页面。它会列出刚才创建的三个接口；展开某个接口后，可以点击 Try it out 填写参数并发送请求，不一定每次都要手写 curl 命令。

FastAPI 能生成这份页面，是因为路由、函数参数和 UserCreate 模型已经描述了接口的基本结构。同一份结构还可以通过下面的地址查看：

http://127.0.0.1:8001/openapi.json

这里返回的是 OpenAPI 格式的接口描述，/docs 页面会读取它并展示成可操作的文档。本次请求这两个地址都返回了 200。读取 /openapi.json 后，可以看到三个实际路由：

/
/users
/users/{user_id}

UserCreate 的 name 和 age 也都出现在必填字段中。这说明接口文档不是另外维护的一份静态文字，而是从当前路由和数据模型生成的。

FastAPI 在这个 Demo 中做了什么​

回头看这几个实践步骤，FastAPI 主要完成了这些工作：

写下的代码FastAPI 完成的工作
@app.get()、@app.post()根据路径和请求方法找到要执行的函数
user_id: int从 URL 取值，尝试转换成整数，并处理不符合要求的输入
user: UserCreate读取 JSON 请求体，并使用 Pydantic 转换、校验字段
返回 Python 字典生成 JSON 响应
路由和数据模型生成 OpenAPI 描述和 /docs 文档

它没有替我决定用户数据应该怎样保存，也没有自动完成数据库、登录鉴权或部署配置。这些属于后端项目的其他部分，不是这个最小 Demo 已经解决的问题。

总结​

回到开头的问题：FastAPI 是一个帮助 Python 程序接收 HTTP 请求并返回响应的 Web 框架。

这次从零完成了一个小项目：

  1. 创建并启动 FastAPI 应用；
  2. 用路由把 URL 和 Python 函数连接起来；
  3. 接收并检查路径参数；
  4. 用 Pydantic 模型接收 JSON 请求体；
  5. 在 /docs 中查看并调试接口。

这次实际验证只覆盖了这些基础能力。通过这个 Demo 可以确认：浏览器或其他客户端发来的 HTTP 请求，并不是直接变成 Python 函数参数的；FastAPI 在中间完成了路由匹配、数据解析、基础校验和响应转换。
