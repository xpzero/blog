Embedding：把"意思相近"变成一个能算的数

博客搜索有个经典问题：文章里写的是"垂直水平居中"，用户搜"元素居中对齐"，关键词匹配一条都命中不了。字符串层面它们确实不相等——但人一眼能看出是一个意思。

KV Cache 与自回归：为什么首字慢、后面快

用过流式输出的聊天界面都见过这个节奏：发出问题后要等一小会儿，第一个字才蹦出来；可一旦开始，后面的字就哗哗地流。为什么"启动"和"续写"速度差这么多？

Token 与分词：模型不按"字"读你的文本

"你好"是几个字？人会说 2 个字，电脑存储它要占 6 个字节，而在大模型的世界里还有第三种量法：Token 数。模型能处理多长的输入按它算、接口用量按它算，但它既不是字数也不是字节数。

Transformer 全景：从 token ID 到下一个词

前两篇留了一个断层：Token 把文本切成了数字 ID，Embedding 说模型内部处理的是向量——那么从"一串 ID 进去"到"下一个词出来"，中间到底经过了什么？

上下文窗口：长了为什么崩，中间为什么被漏掉

把一份长文档丢给模型让它回答问题，常见两种翻车：要么直接报错"超出长度限制"，要么答是答了，但引用的全是文档开头和结尾的内容，中间部分像没读过一样。

从零手写 Agent（五）：让 Agent 读写本地文件

前四篇的工具都是玩具：写死的假天气、一个小计算器。真正有用的 Agent 得能碰到真实的东西——比如「帮我看看这个文件里写了什么」、「把整理好的内容存成 markdown」。

从零手写 Agent（八）：把它接上网页

命令行里的 Agent 已经能用了，但它只属于一个终端窗口。想要 ChatGPT 那样的网页界面——消息气泡、逐字上屏、会话列表——该怎么把现有的代码接上去？

从零手写 Agent（六）：接上联网搜索，同时接上风险

问 Agent 一件最近发生的事，它会告诉你「我的知识截止到某个时间」。模型的知识来自训练数据，训练完成之后的事情它一概不知。

从零手写 Agent（四）：流式输出，以及被切碎的工具调用

上一篇的 Agent 能连续对话了，但用起来有个明显的难受之处：问一个需要长篇回答的问题，屏幕上什么都没有，几秒后突然「啪」地出现一整段。

位置编码：为什么要额外告诉模型"顺序"

"狗咬人"和"人咬狗"，词完全一样，意思天差地别。区分它们靠的是语序——但 Transformer 的注意力机制，天生看不见语序。

大模型学习：从零拆开黑盒的入门地图

同一个问题问两次，答案不一样；对话拉长了，它开始忘记前面说过什么；明明一本正经，给出的资料却根本不存在。天天用 Cursor 和聊天助手，这些现象人人都撞见过，但要解释"为什么"，光会用是不够的——输入一段话、吐出一段话，中间是个黑盒。

概率与采样：temperature 到底改了什么

同一个问题问两遍，答案经常不一样。这有点反常识：计算器按一万遍 1+1 都是 2，为什么大模型不是？

注意力机制：模型怎么决定"该看哪几个词"

"这家店的服务很差，但它的咖啡确实不错"——要判断"它"指什么，人会自然地回头找"这家店"。模型也要解决同一个问题：处理某个位置时，前文那么多 token，哪些相关、该参考多少？

训练与微调：模型的"性格"从哪来

前面八篇拆完了推理——一句话进去、一段话出来的全过程。但有个问题一直悬着：那几百亿个参数里的"知识"和"分寸"是哪来的？为什么它会礼貌地拒绝出格请求，为什么它"记得"的资料会过时，又为什么它会自信地记错？
