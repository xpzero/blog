Day 7：Prompt 工程

怎么问大模型，才能让它答得好？这就是 Prompt 工程要解决的问题。

为什么需要 Prompt 工程？​

大模型不知道自己是谁、你要什么、想要什么格式。

你得告诉它。

四个基本原则​

1. 明确具体​

模糊的 Prompt 换来模糊的回答：

❌ 差的：

写点关于猫的东西

✅ 好的：

写一篇 200 字的科普短文，介绍家猫的睡眠习惯。
面向 10 岁儿童，语气轻松有趣。

2. 给上下文​

不说背景，模型只能瞎猜：

❌ 差的：

优化这段代码

✅ 好的：

这段 Python 代码处理 10GB CSV 文件时很慢，
请优化性能，优先考虑内存效率。

3. 指定格式​

不说格式，模型随便写：

❌ 差的：

列出远程工作的好处

✅ 好的：

用表格列出远程工作的 5 个好处和 3 个挑战，
包含：方面、描述、应对建议。

4. 角色设定​

给模型一个身份：

你是一位有 10 年经验的 Python 工程师。
请审查以下代码，关注性能问题。

模型会站在专家角度回答。

进阶技巧​

Few-shot（给例子）​

给几个示例，模型按例子模仿：

翻译成英文：

例子：
中文：你好
英文：Hello

中文：谢谢
英文：Thank you

现在翻译：
中文：很高兴认识你
英文：

Chain-of-Thought（逐步思考）​

让模型一步步想，减少错误：

问题：一个农场有鸡和兔，头共 35，脚共 94。
鸡和兔各多少只？

请一步一步思考。

输出模板​

给具体结构：

分析这个产品，输出：
## 产品名称
[名称]

## 目标用户
[用户群体]

## 核心功能
- [功能 1]
- [功能 2]

常见错误​

错误差例子好例子
太模糊"写点东西""写 800 字博客，关于远程工作"
没背景"优化代码""10GB 数据内存溢出，请优化"
没格式"总结一下""3 个 bullet，每个不超 20 字"

踩坑记录​

坑1：Prompt 不是越长越好 有时候长 Prompt 反而让模型分心。简洁、直接、关键信息到位就够了。

坑2：例子不是越多越好 2-3 个例子比 10 个例子更有效。太多例子可能让模型过度拟合。

坑3：角色设定可能适得其反 "你是 XX 领域的专家"有时候会让模型过于"专业"而不够实用。根据需求调整。

总结​

  • 明确具体，给上下文，指定格式，角色设定
  • Few-shot 给例子，CoT 引导推理
  • Prompt 需要迭代优化，没有一次就完美的

明天聊 RAG，怎么给大模型加知识。
