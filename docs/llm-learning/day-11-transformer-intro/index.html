Transformer 入门：生成文字前模型在看什么

聊天模型输出下一个字之前，不是在资料库里直接查答案。它会先把已有文字拆成词元，并让每个位置参考上下文，再选择最可能的下一个词元。Transformer 是完成这件事的主流结构。

从一句话开始理解​

读到“我把书放进包里，因为它很重”时，“它”更可能指书。Transformer 的注意力机制会让“它”的表示参考“书”“包”“很重”等位置，相关程度由训练数据学出来。

输入词元 -> 加上位置信息 -> 注意力参考上下文 -> 预测下一个词元

位置很重要。只看词集合无法区分“狗追猫”和“猫追狗”，所以模型还会收到每个词所处位置的信号。

观察一个简化注意力​

这个例子用人为设定的权重模拟“它”查看哪些词。复制到 attention_demo.py 后运行 python attention_demo.py：

tokens = ["书", "放进", "包", "它", "很重"]
scores = [0.60, 0.05, 0.15, 0.02, 0.18]

for token, score in zip(tokens, scores):
    bar = "#" * round(score * 20)
    print(f"{token:4} {bar} {score:.0%}")

输出中“书”的条形最长，表示当前“它”主要参考它。真实 Transformer 不是人工写分数，而是用大量参数计算；一层里还有多组并行的注意力，多层会反复更新这些表示。

两种常见结构​

  • 编码器擅长把整段输入读懂，常用于分类、检索等任务。
  • 解码器按顺序生成内容，并遮住未来位置，常用于 GPT 一类对话模型。

原始 Transformer 同时有编码器和解码器，适合翻译这类“读一段、写一段”的任务。

限制​

  • 上下文越长，普通注意力的计算和显存成本通常越高。
  • 相关权重不是事实依据，也不能说明模型一定理解了句子。
  • 模型只根据训练学到的模式生成，可能自信地给出错误内容。
