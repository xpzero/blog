Transformer

Embedding 已经把 Token 表示成数值，但单个数值还不知道前后文。聊天模型为什么能根据前文继续写一句话，而不是只看最后一个词？现代语言模型常用 Transformer 架构来处理一段 Token 之间的关系。

从补全一句话观察​

输入"把配置文件放到"时，模型生成路径、目录或其他后续内容，会参考前面的"配置文件"和"放到"。这不是规则引擎逐字查表，而是模型先为输入建立上下文相关的表示，再预测下一个 Token。

Token ID -> 向量 -> 多层 Transformer -> 下一个 Token 的候选分数

这里的"候选分数"还要经过采样策略才能成为实际输出，具体行为由模型和接口参数共同决定。

它由什么组成​

Transformer 是 2017 年论文提出的一类神经网络架构。其基本层会让序列中的位置交换信息，再对每个位置做进一步变换。Self-Attention 是其中用来计算位置之间关联的模块。

语言模型还需要位置信息，因为"我打你"和"你打我"包含相同的字，但顺序不同。不同实现会用不同的位置表示方式，不必把某一种实现当成所有 Transformer 的固定结构。

Encoder 和 Decoder​

原始 Transformer 包含 Encoder 和 Decoder。Encoder 更适合为完整输入产生表示，Decoder 可以在生成时按顺序使用已生成的内容。后续模型会选择其中的一部分或改造结构，因此看到 Transformer 时应先确认该模型的架构和任务。

为什么它影响工程选择​

注意力计算会随着输入长度增加而增加资源消耗。长提示词不只是占用上下文窗口，也可能影响延迟和成本。模型服务会使用不同的注意力实现和缓存策略，实际限制以服务文档及观测结果为准。

容易误解的地方​

  • Transformer 是架构类别，不是某一个具体产品。
  • "模型理解了"是方便交流的说法，不代表它拥有人的理解或可靠事实知识。
  • 更大或层数更多不自动意味着更适合任务，还要评估质量、速度、成本和部署条件。
