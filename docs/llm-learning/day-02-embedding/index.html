Embedding

Token 把文本切成模型可处理的单位，但模型还需要用数值处理这些单位。给文档站加搜索时，用户输入"怎么处理请求超时"，不一定会写出文档里的"网络错误"。Embedding 是处理这类表达接近、用词不同的检索需求的一种表示方法。

一个可观察的场景​

准备三条文本：

A: 如何处理请求超时
B: 网络请求失败时怎样重试
C: CSS 如何实现居中

把查询和每条文本交给同一个 Embedding 模型，得到数值向量后，再按模型建议的相似度方法排序。A 和 B 往往会比 C 更靠前，但这不是保证: 结果取决于模型、语言、文本长度和查询方式。

Embedding 是什么​

Embedding 可以理解为把文本映射为一串浮点数的过程，这串数就是向量。向量本身没有可直接阅读的单个维度含义；它的价值在于，同一模型产生的向量可以用距离或相似度进行比较。

文本 -> Embedding 模型 -> 向量 -> 相似度排序

它常用于语义搜索、相似内容推荐、聚类，以及 RAG 中的候选文档检索。

最小实现需要什么​

实现检索至少需要四步：

  1. 用同一个模型为文档片段生成向量，并保存文本、来源和更新时间等元数据。
  2. 用同一个模型为用户查询生成向量。
  3. 在已保存的向量中找出相近的若干条。
  4. 把检索结果展示给用户，或交给后续的生成模型。

向量数据库可以加速第 3 步，但小数据量也可以先用普通数组和库函数验证流程。不同模型的向量空间没有共同语义，替换模型后通常需要重新生成索引。

选择与评估​

先用目标语言和真实查询准备一组小型评测集: 每个查询标记哪些文档是相关的。比较候选模型时，观察相关内容是否排在前面，同时检查延迟、存储和更新成本。

不要只看向量维度或宣传指标。维度、最大输入长度、是否需要在查询前添加前缀，都应以所用模型的文档为准。

局限​

  • 语义相近不等于事实正确，检索结果仍需要来源和权限控制。
  • 精确的标识符、错误码和日期有时更适合关键词或过滤条件。
  • 文档切得太短会丢上下文，切得太长又会混入无关信息。
  • 向量可能泄露文本特征，私有数据仍需要按安全要求存储和访问。
