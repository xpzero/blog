Day 4：上下文窗口与长文本处理

学习目标​

理解上下文窗口的概念、限制，以及如何在实际应用中处理长文本。

理论学习​

什么是上下文窗口？​

  • 上下文窗口（Context Window）是模型能「记住」的 Token 数量上限
  • 包括：系统提示 + 历史对话 + 当前输入
  • 超过窗口限制，最早的内容会被「遗忘」

常见模型的上下文窗口​

模型上下文窗口约等于
GPT-3.54K-16K tokens3-12 页文档
GPT-48K-128K tokens6-96 页文档
Claude 3200K tokens150 页文档
Kimi200K tokens150 页文档

上下文窗口的实际影响​

场景 A：长文档分析

问题：要分析一本 300 页的书，但模型只能处理 50 页
解决：分块处理 → 逐章摘要 → 综合总结

场景 B：长时间对话

问题：聊了很久后，模型「忘记」了之前的设定
原因：早期消息被挤出上下文窗口
解决：定期总结关键信息，或重新提供上下文

长文本处理策略​

策略适用场景说明
分块（Chunking）长文档将文本切成小块，分批处理
滑动窗口连续分析每次保留部分上文，引入新内容
摘要压缩历史对话定期将长对话压缩成摘要
RAG（检索增强）知识库问答只把相关片段放入上下文

RAG 是什么？​

RAG = Retrieval-Augmented Generation（检索增强生成）

简单理解：

  • 传统方式：把整本书塞进脑子 → 书太厚塞不下
  • RAG 方式：先查目录找相关章节 → 只读那几页 → 回答问题

动手实践​

任务：体验上下文限制​

  1. 测试你的模型上下文

    • 复制一段长文本（约 2000 字）
    • 让模型总结开头、中间、结尾的内容
    • 观察是否能准确回忆全文

  2. 模拟「遗忘」现象

    • 开始一个新对话，设定一个规则（如「请用表格回答」）
    • 持续对话 20+ 轮，每轮内容较长
    • 观察模型何时开始「忘记」初始规则

  3. 尝试分块处理

    • 找一篇长文章（超过 3000 字）
    • 将其分成 3 段
    • 先让模型分别总结每段
    • 再让模型基于三个摘要给出整体总结

检查点问题​

  1. 如果你的文档有 10 万字，而模型上下文只有 4K tokens，你应该怎么处理？
  2. 为什么有时候模型会「忘记」对话早期的内容？
  3. RAG 和直接放全文进上下文，各有什么优缺点？

今日产出​

  • 测试并记录你的常用模型的上下文限制
  • 体验一次「模型遗忘」现象
  • 尝试分块处理一篇长文档
  • 回答检查点问题
