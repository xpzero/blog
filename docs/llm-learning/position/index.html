位置编码：为什么要额外告诉模型"顺序"

"狗咬人"和"人咬狗"，词完全一样，意思天差地别。区分它们靠的是语序——但 Transformer 的注意力机制，天生看不见语序。

上一篇拆过注意力的计算：Query 和所有 Key 打分、按权重混合 Value。整个过程里没有任何一步用到"这个 token 排第几"——把输入序列打乱重排，每对 Q·K 的点积结果一个都不会变。术语说，注意力对输入是置换不变的（permutation invariant），它看到的是一袋无序的词。

所以顺序必须额外注入。这篇讲注入的思路和主流方案，照旧不推公式。

问题和解法，一张图​

左半边是没有位置信息的世界："dog bites man" 和 "man bites dog" 进入注意力后是同一袋 token，模型无从区分。右半边是解法：每个 token 的向量在进入第一层之前，先和自己的位置信息（pos 0、pos 1、pos 2）合并，此后每个向量自带"我排第几"，注意力打分时自然能把顺序考虑进去。

这个操作生活里很常见：一沓没有页码的手稿被风吹散就再也排不回去，所以打印时要在每页角上印页码——数据本身不含位置，就把位置写进数据里。区别在于"写"的方式：不是印个数字上去，而是把位置也表示成向量，和词向量融合。

位置怎么变成向量​

难点在于：位置是个整数（0、1、2、…），词向量是几千维的浮点数组，两者怎么"融合"？几代方案：

正弦位置编码：用波形给位置编码​

原始论文的方案。最朴素的想法是直接把位置数字塞进去（第 1 个词标 1、第 100 个标 100），但这样有麻烦：数值随长度无限膨胀，第 10000 位的"100 00"会把向量里的语义信息彻底压扁；全部除以总长度归一化也不行——同一个"第 5 位"在 10 个词的句子里是 0.5、在 100 个词里是 0.05，含义漂移。

论文的解法是不用一个数，而用一组不同频率的波：为每个位置生成一个和词向量同维度的向量，每一维的数值取自一条正弦/余弦曲线，有的波振荡得快、有的极慢。直觉上像钟表——只看秒针分不清 1 分钟前后（转回同一位置了），只看时针又分不清相邻两秒；但秒针 + 分针 + 时针合起来，任何时刻都是唯一的，且数值永远在表盘范围内。快波区分相邻位置，慢波区分远近段落，每个位置得到一个独一无二又有界的"指纹"。这个位置向量直接加到词向量上。

好处是不用训练、任意长度都能算；但这套方案基本已经退役了，看老资料时认识它即可。

可学习位置向量：再查一张表​

GPT-2、BERT 一代的方案：像词表一样建一张"位置表"，pos_table[0]、pos_table[1]……每个位置的向量由训练学出来。简单直接，但表建多大，模型就最多认多长——训练时只见过 1024 个位置，第 1025 个 token 就没有向量可查。这是早期模型上下文长度死板的原因之一。

RoPE：现在的主流​

当代开源模型（Llama、Qwen、DeepSeek 等）几乎都用 RoPE（Rotary Position Embedding，旋转位置编码）。它换了个思路：不再把位置信息加到词向量上，而是在注意力打分前，按位置把 Q 和 K 向量旋转一个角度——想象每个向量是表盘上的一根指针，位置 0 不转，位置 1 转 10°，位置 2 转 20°……位置越靠后转得越多。

妙处在于一个几何事实：两根指针的点积只跟它们的夹角差有关。"位置 3 的 Query"对"位置 1 的 Key"，夹角差是 20°；换到"位置 103 对位置 101"，夹角差还是 20°——打分结果携带的是"隔 2 个词"这个相对距离，而不是各自的绝对座位号。

前两种方案编码的都是绝对位置，模型要自己费劲学出"第 5 位减第 3 位等于隔 2 位"；RoPE 直接把相对距离送到注意力手上。而相对距离恰恰是语言里更本质的量——"形容词紧挨着名词"这种模式，跟它们出现在第 5 位还是第 5000 位无关。同一个模式学一次就能用在任何位置，这也是 RoPE 在长文本上更稳的原因之一。

推导见文末 RoPE 论文；只需要记住结论：RoPE 编码的是相对位置，且不占用词向量的加法空间。

这件事和你调 API 有什么关系​

位置编码听起来最"纯理论"，但它直接决定一个工程属性：上下文窗口能不能外推。

  • 可学习位置表：超出表长直接没法算，硬上限。
  • RoPE：超出训练长度时模型质量会下降，但存在不重训、只调整旋转频率就能拉长窗口的技巧（YaRN、位置插值等，见文末链接）。近年模型窗口从 4k 一路涨到 128k 甚至更长，很大程度是在 RoPE 上做文章。

所以看到"某模型支持 1M 上下文"时，值得多问一句：是训练时真见过这么长，还是外推出来的？两者在长文本上的实际表现可能差很多——这个话题第 8 篇展开。
