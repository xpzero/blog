Day 8：注意力机制进阶

原版 Attention 有个致命问题：O(n²) 复杂度。序列一长，内存直接爆炸。这也是为什么早期 GPT 只能处理 1024 Token，想更长就得改架构。

效率问题​

复杂度分析​

操作时间复杂度空间复杂度
Self-AttentionO(n²d)O(n²)
Feed-ForwardO(nd²)O(nd)

n = 序列长度，d = 模型维度

实际影响：

  • n=512，d=768：Attention 占 60% 计算
  • n=4096，d=4096：Attention 占 90% 计算，内存 64GB

这就是为啥早期 GPT 只能处理 1024 Token。

稀疏注意力（Sparse Attention）​

局部注意力（Local Attention）​

只关注附近的 Token，远处的不管。

每个位置只 attend 到窗口大小 w 内的位置
复杂度从 O(n²) 降到 O(nw)

问题：长距离依赖丢失

全局注意力（Global Attention）​

选一些特殊位置（如 [CLS]），让所有位置都能 attend 到它。

Longformer 的做法：

  • 局部滑动窗口
  • 全局位置（如每 128 个位置选一个）
  • 复杂度 O(nw + ng)，g 是全局位置数

随机注意力（Random Attention）​

每个位置随机选几个位置 attend。

BigBird = 局部 + 全局 + 随机

线性注意力（Linear Attention）​

核心思想​

把 softmax(QK^T)V 改写成线性形式。

原版：

Attention(Q,K,V) = softmax(QK^T/√d)V

线性版本：

Attention(Q,K,V) = φ(Q)φ(K)^TV
                 = φ(Q)(φ(K)^TV)

先算 φ(K)^TV，复杂度从 O(n²d) 降到 O(nd²)。

Performer​

用随机特征映射近似 softmax。

import torch
import torch.nn as nn

class PerformerAttention(nn.Module):
    def __init__(self, dim, heads=8, nb_features=64):
        super().__init__()
        self.heads = heads
        self.nb_features = nb_features
        
        # 随机投影矩阵
        self.proj_matrix = torch.randn(dim, nb_features)
        
    def forward(self, q, k, v):
        # 随机特征映射
        q = self.softmax_kernel(q)
        k = self.softmax_kernel(k)
        
        # 线性注意力
        kv = torch.einsum('...nd,...ne->...de', k, v)
        out = torch.einsum('...nd,...de->...ne', q, kv)
        return out
    
    def softmax_kernel(self, x):
        # 随机傅里叶特征
        x = x @ self.proj_matrix.to(x.device)
        return torch.exp(x - x.max(dim=-1, keepdim=True).values)

Flash Attention​

核心思想​

不在 HBM（高带宽内存）上存巨大的 Attention 矩阵，而是在 SRAM（高速缓存）上分块计算。

HBM: 大但慢（1.5TB/s）
SRAM: 小但快（19TB/s）

分块计算​

# 伪代码
for block_q in Q_blocks:
    for block_k, block_v in zip(K_blocks, V_blocks):
        # 在 SRAM 上计算小块 Attention
        scores = block_q @ block_k.T
        attn = softmax(scores)
        out_block = attn @ block_v
    # 写回 HBM
    write_to_HBM(out_block)

效果：

  • 内存从 O(n²) 降到 O(n)
  • 速度提升 2-4 倍
  • 越长序列收益越大

限制：

  • 需要特定硬件支持（A100+）
  • 实现复杂，一般用现成的库
# 使用 Flash Attention
from flash_attn import flash_attn_func

output = flash_attn_func(q, k, v, causal=True)

多查询注意力（Multi-Query Attention）​

问题​

标准 Multi-Head Attention，每个头有自己的 K、V：

内存 = batch × heads × seq_len × dim × 2 (K+V) × 2 (FP16)

推理时 KV Cache 占大量内存。

解决方案​

所有头共享同一组 K、V，只有 Q 不同。

# 标准 MHA
self.W_k = nn.Linear(dim, dim)  # 每个头独立
self.W_v = nn.Linear(dim, dim)

# MQA
self.W_k = nn.Linear(dim, dim // heads)  # 共享
self.W_v = nn.Linear(dim, dim // heads)

效果：

  • KV Cache 内存减少 heads 倍（通常 8-32 倍）
  • 推理速度提升
  • 质量略有下降，但可接受

分组查询注意力（GQA）​

折中方案：几个头共享一组 K、V。

MHA: 8 个头，8 组 K/V
GQA: 8 个头，2 组 K/V（每 4 个头一组）
MQA: 8 个头，1 组 K/V

LLaMA 2 用 GQA，平衡内存和质量。

位置编码进阶​

RoPE（Rotary Position Embedding）​

旋转位置编码，用旋转矩阵注入位置信息。

import torch
import torch.nn as nn

def apply_rotary_pos_emb(q, k, cos, sin):
    # 旋转 q 和 k
    q_rot = (q * cos) + (rotate_half(q) * sin)
    k_rot = (k * cos) + (rotate_half(k) * sin)
    return q_rot, k_rot

def rotate_half(x):
    # 交换后半部分并取负
    x1, x2 = x.chunk(2, dim=-1)
    return torch.cat([-x2, x1], dim=-1)

优点：

  • 相对位置编码，外推性好
  • 长序列表现稳定
  • LLaMA、PaLM 都在用

ALiBi（Attention with Linear Biases）​

不给位置加 embedding，直接在 Attention 分数上加惩罚。

score = QK^T/√d - m × |i-j|

m 是预设的斜率，|i-j| 是位置距离。

效果：

  • 训练短序列，推理长序列（外推）
  • 不需要位置编码
  • BLOOM 在用

实际选择建议​

场景推荐方案
长文档（>4K）Longformer、BigBird
资源紧张Performer、Linear Attention
A100+ 显卡Flash Attention
推理优化MQA、GQA
新模型设计RoPE

今天学了啥​

  • 标准 Attention 的 O(n²) 问题是瓶颈
  • 稀疏注意力：局部 + 全局 + 随机
  • 线性注意力：把复杂度降到 O(n)
  • Flash Attention：分块计算，省内存提速
  • MQA/GQA：减少 KV Cache，加速推理
  • RoPE/ALiBi：更好的位置编码，支持外推

效率优化是 LLM 工程的核心，选什么方案取决于你的硬件和场景。
