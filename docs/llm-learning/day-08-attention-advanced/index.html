Day 8：注意力机制进阶

原版 Attention 有个问题：O(n²) 复杂度。序列一长，内存直接爆炸。想处理长文本，就得改架构。

效率问题​

复杂度分析​

操作时间复杂度空间复杂度
Self-AttentionO(n²d)O(n²)
Feed-ForwardO(nd²)O(nd)

n = 序列长度，d = 模型维度

实际影响：

  • n=512：Attention 占 60% 计算
  • n=4096：Attention 占 90% 计算，内存 64GB

这就是瓶颈。

稀疏注意力​

局部注意力​

只关注附近的 Token，远处的不管。

每个位置只 attend 到窗口大小 w 内的位置
复杂度从 O(n²) 降到 O(nw)

问题：长距离依赖丢失

全局注意力​

选一些特殊位置（如 [CLS]），让所有位置都能 attend 到它。

Longformer 的做法：

  • 局部滑动窗口
  • 全局位置（每 128 个位置选一个）
  • 复杂度 O(nw + ng)

随机注意力​

每个位置随机选几个位置 attend。

BigBird = 局部 + 全局 + 随机

线性注意力​

核心思想​

把 softmax(QK^T)V 改写成线性形式，复杂度从 O(n²d) 降到 O(nd²)。

Performer：用随机特征映射近似 softmax。

Flash Attention​

核心思想​

不在 HBM（高带宽内存）上存巨大 Attention 矩阵，在 SRAM（高速缓存）上分块计算。

HBM: 大但慢（1.5TB/s）
SRAM: 小但快（19TB/s）

效果​

  • 内存从 O(n²) 降到 O(n)
  • 速度提升 2-4 倍
  • 越长序列收益越大

限制：需要 A100+ 硬件支持。

from flash_attn import flash_attn_func

output = flash_attn_func(q, k, v, causal=True)

多查询注意力​

问题​

标准 Multi-Head Attention，每个头有自己的 K、V。推理时 KV Cache 占大量内存。

解决方案​

MQA：所有头共享同一组 K、V。

GQA：几个头共享一组 K、V（LLaMA 2 在用）。

MHA: 8 个头，8 组 K/V
GQA: 8 个头，2 组 K/V
MQA: 8 个头，1 组 K/V

效果：KV Cache 内存减少 heads 倍（通常 8-32 倍），推理速度提升。

位置编码进阶​

RoPE（旋转位置编码）​

用旋转矩阵注入位置信息。

优点：

  • 相对位置编码，外推性好
  • 长序列表现稳定
  • LLaMA、PaLM 在用

ALiBi​

不给位置加 embedding，直接在 Attention 分数上加惩罚。

score = QK^T/√d - m × |i-j|

效果：训练短序列，推理长序列（外推）。BLOOM 在用。

选型建议​

场景推荐方案
长文档（>4K）Longformer、BigBird
资源紧张Performer、Linear Attention
A100+ 显卡Flash Attention
推理优化MQA、GQA
新模型设计RoPE
