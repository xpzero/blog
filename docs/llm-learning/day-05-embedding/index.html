Day 5：嵌入与向量数据库

嵌入（Embedding）是连接文本语义与机器计算的桥梁——让"苹果"和"水果"在数学上更接近。

什么是嵌入（Embedding）？​

一句话定义： 将离散的文本/图像/音频转换为连续的数值向量的技术。

类比理解：

  • 就像给每个词发一个多维坐标
  • 语义相近的词，坐标也相近
  • 机器通过坐标"理解"词与词的关系

直观示例​

"国王" - "男人" + "女人" ≈ "女王"

向量计算：
[0.2, 0.5, ...] - [0.3, 0.1, ...] + [0.4, 0.6, ...] 
≈ [0.3, 1.0, ...]  ← 接近"女王"的向量

经典案例： Google 的 Word2Vec 在 2013 年展示了这个神奇性质。

嵌入的维度​

维度说明示例
低维50-100 维早期 Word2Vec
中维384-768 维轻量级模型（all-MiniLM）
高维1024-4096 维GPT、BERT 等大型模型

维度越高：

  • ✅ 表达能力越强
  • ❌ 存储成本越高
  • ❌ 计算量越大

嵌入模型选择​

模型维度特点适用场景
text-embedding-3-small1536OpenAI 轻量版通用场景，成本低
text-embedding-3-large3072OpenAI 高性能需要高精度匹配
all-MiniLM-L6-v2384开源轻量本地部署，资源受限
bge-large-zh1024中文优化中文语义搜索
m3e-base768中文开源中文 RAG 应用

选择建议：

  • 英文为主 + 云端 → OpenAI embedding
  • 中文为主 + 本地 → bge 或 m3e
  • 资源受限 → all-MiniLM（384维）

嵌入如何工作？​

训练过程（简化版）​

核心思想： 让上下文相似的词，嵌入向量也相似

训练数据：

"猫坐在垫子上"

上下文对：
("猫", "坐") → 正样本
("猫", "垫子") → 正样本
("猫", "狗") → 负样本（随机采样）

训练目标：

  • 正样本的向量距离近
  • 负样本的向量距离远

嵌入的数学表示​

# 伪代码：文本 → 向量
def embed(text: str) -> list[float]:
    # 经过神经网络编码
    vector = neural_network.encode(text)
    # 归一化（可选，便于计算相似度）
    vector = normalize(vector)
    return vector  # 例如 384 维或 1536 维

# 示例
vec_apple = embed("苹果")      # [0.1, 0.3, 0.5, ...]
vec_fruit = embed("水果")      # [0.2, 0.4, 0.4, ...]  ← 接近苹果
vec_phone = embed("苹果手机")   # [0.8, 0.1, 0.2, ...]  ← 远离水果

语义相似度匹配​

余弦相似度（Cosine Similarity）​

最常用的相似度计算方法。

公式：

cos(θ) = (A · B) / (||A|| × ||B||)

直观理解：

  • 两个向量的"夹角"越小，相似度越高
  • 取值范围：-1（完全相反）到 1（完全相同）
  • 通常用于已归一化的向量

代码示例：

import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# 示例
vec1 = embed("机器学习")
vec2 = embed("深度学习")
vec3 = embed("苹果派")

sim_12 = cosine_similarity(vec1, vec2)  # ≈ 0.85（高相似）
sim_13 = cosine_similarity(vec1, vec3)  # ≈ 0.20（低相似）

欧氏距离（Euclidean Distance）​

另一种常用的距离度量。

公式：

d = √(Σ(ai - bi)²)

特点：

  • 直接计算向量空间中的直线距离
  • 对向量的绝对位置敏感
  • 适合已归一化的向量

选择建议：

  • 余弦相似度 → 关注方向/语义
  • 欧氏距离 → 关注绝对位置

相似度阈值参考​

相似度语义关系应用场景
> 0.9几乎同义去重、精确匹配
0.7-0.9高度相关推荐、相关搜索
0.5-0.7有一定关联扩展搜索
< 0.5关联较弱通常过滤掉

向量数据库​

为什么需要向量数据库？​

问题： 有 100 万条文本，如何快速找到与查询最相似的 10 条？

暴力搜索：

# 计算查询与所有文本的相似度 → O(n)
similarities = [cosine_similarity(query_vec, vec) for vec in all_vectors]
top_k = sorted(similarities, reverse=True)[:10]
# 100万条需要几秒到几十秒，太慢！

向量数据库：

  • 使用近似最近邻（ANN）算法
  • 100万条 → 毫秒级响应
  • 支持索引、过滤、持久化

核心概念：近似最近邻（ANN）​

精确最近邻： 找到绝对最接近的 K 个向量 近似最近邻： 找到"足够接近"的 K 个向量（牺牲少量精度换取速度）

权衡：

  • 构建索引时间 vs 查询时间
  • 存储空间 vs 查询精度
  • 召回率 vs 响应速度

主流 ANN 算法​

1. HNSW（Hierarchical Navigable Small World）​

原理： 构建多层图结构，类似"高速公路"系统

Layer 2（顶层）: 稀疏连接，长距离跳跃
Layer 1（中层）: 中等密度
Layer 0（底层）: 密集连接，精确查找

查询时：从顶层快速接近 → 逐层精确定位

特点：

  • ✅ 查询速度快
  • ✅ 召回率高（>95%）
  • ❌ 内存占用较大
  • ❌ 构建索引较慢

适用： 内存充足，追求速度的场景

2. IVF（Inverted File Index）​

原理： 先聚类，再搜索

步骤：
1. 将向量空间分成 N 个簇（K-means 聚类）
2. 查询时，先找到最近的几个簇
3. 只在这些簇内精确搜索

示例：100万条分成1000个簇
搜索范围从 100万 → 约 1000条（减少99.9%）

特点：

  • ✅ 内存效率高
  • ✅ 构建速度快
  • ❌ 召回率略低于 HNSW
  • ❌ 需要调参（簇数量）

适用： 大规模数据，内存受限

3. 其他算法​

算法特点代表产品
LSH局部敏感哈希，理论保证Faiss（部分）
PQ乘积量化，极致压缩Faiss
DiskANN磁盘存储，超大规模微软开源

主流向量数据库对比​

数据库特点适用场景
Pinecone全托管，易用快速启动，不想运维
Weaviate开源，多模态需要本地部署
Milvus/Zilliz高性能，云原生大规模生产环境
Chroma轻量，嵌入式开发测试，小项目
pgvectorPostgreSQL 扩展已有 PG 基础设施
FaissMeta 开源库需要深度定制
QdrantRust 编写，高性能高性能需求

向量数据库核心操作​

# 伪代码：向量数据库基本操作

# 1. 创建集合（类似 SQL 的表）
db.create_collection(
    name="documents",
    dimension=1536,  # 向量维度
    metric="cosine"  # 相似度度量
)

# 2. 插入数据
db.insert(
    collection="documents",
    vectors=[vec1, vec2, vec3],
    metadata=[
        {"id": "doc1", "title": "机器学习入门"},
        {"id": "doc2", "title": "深度学习进阶"},
        {"id": "doc3", "title": "苹果派食谱"}
    ]
)

# 3. 相似度搜索
results = db.search(
    collection="documents",
    query_vector=embed("神经网络"),
    top_k=5,
    filter={"category": "技术"}  # 元数据过滤
)
# 返回：[{id: "doc1", score: 0.92, ...}, {id: "doc2", score: 0.88, ...}]

RAG 中的嵌入与向量数据库​

完整 RAG 流程​

┌─────────────────────────────────────────────────────────────┐
│                        准备阶段（离线）                        │
├─────────────────────────────────────────────────────────────┤
│  原始文档 → 文本分块 → Embedding 模型 → 向量 → 存入向量数据库      │
│     ↓           ↓            ↓          ↓          ↓        │
│   PDF/网页    500-1000字   text-embedding  1536维   Pinecone │
│   Markdown    重叠100字    bge-large-zh    1024维   Chroma   │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                        查询阶段（在线）                        │
├─────────────────────────────────────────────────────────────┤
│  用户提问 → Embedding 模型 → 向量 → 向量检索 → Top K 片段 → LLM │
│     ↓            ↓          ↓        ↓         ↓        ↓   │
│  "什么是RAG?"  同模型编码   查询向量  相似度搜索  相关上下文  生成回答│
└─────────────────────────────────────────────────────────────┘

关键设计决策​

决策点选项影响
分块大小200-1000 Token太小丢失上下文，太大降低精度
分块重叠10-20%保持段落连续性
Top K 值3-10 个片段太少信息不足，太多引入噪声
相似度阈值0.5-0.7过滤低质量匹配
重排序使用 Cross-Encoder提升最终排序质量

动手实践​

任务 1：体验 Embedding​

使用 OpenAI API：

from openai import OpenAI

client = OpenAI()

def get_embedding(text):
    response = client.embeddings.create(
        input=text,
        model="text-embedding-3-small"
    )
    return response.data[0].embedding

# 测试
words = ["苹果", "水果", "苹果手机", "香蕉", "华为", "橙子"]
embeddings = {w: get_embedding(w) for w in words}

# 计算相似度
import numpy as np

def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

print("苹果 vs 水果:", cosine_sim(embeddings["苹果"], embeddings["水果"]))
print("苹果 vs 苹果手机:", cosine_sim(embeddings["苹果"], embeddings["苹果手机"]))
print("苹果 vs 华为:", cosine_sim(embeddings["苹果"], embeddings["华为"]))

预期结果：

  • 苹果 vs 水果：~0.7-0.8（高相似）
  • 苹果 vs 苹果手机：~0.6-0.7（中等相似）
  • 苹果 vs 华为：~0.3-0.4（低相似）

任务 2：本地 Embedding（无需 API）​

使用 sentence-transformers：

pip install sentence-transformers
from sentence_transformers import SentenceTransformer

# 加载轻量级模型（首次下载约 100MB）
model = SentenceTransformer('all-MiniLM-L6-v2')

# 编码文本
sentences = ["机器学习", "深度学习", "苹果派"]
embeddings = model.encode(sentences)

print(f"维度: {embeddings.shape}")  # (3, 384)

# 计算相似度
from sklearn.metrics.pairwise import cosine_similarity
sim_matrix = cosine_similarity(embeddings)
print(sim_matrix)

任务 3：搭建简易语义搜索​

使用 Chroma（纯 Python，无需外部服务）：

pip install chromadb
import chromadb
from sentence_transformers import SentenceTransformer

# 初始化
client = chromadb.Client()
collection = client.create_collection("my_docs")

# 加载模型
model = SentenceTransformer('all-MiniLM-L6-v2')

# 添加文档
docs = [
    "机器学习是人工智能的一个分支",
    "深度学习使用神经网络进行学习",
    "苹果派是一种美味的甜点",
    "Python 是流行的编程语言",
    "神经网络模拟人脑结构"
]

embeddings = model.encode(docs).tolist()
collection.add(
    embeddings=embeddings,
    documents=docs,
    ids=[f"doc{i}" for i in range(len(docs))]
)

# 搜索
query = "AI 技术"
query_embedding = model.encode([query]).tolist()

results = collection.query(
    query_embeddings=query_embedding,
    n_results=3
)

print(f"查询: {query}")
for doc, dist in zip(results['documents'][0], results['distances'][0]):
    print(f"  [{dist:.3f}] {doc}")

今日总结​

核心概念：

  • Embedding = 文本的数值化表示
  • 语义相似 = 向量空间中的距离近
  • 向量数据库 = 高效存储 + 近似最近邻搜索

关键技术：

  • 余弦相似度：最常用的相似度计算
  • HNSW：高速ANN算法（内存换速度）
  • IVF：高效ANN算法（聚类减少搜索空间）

RAG 核心流程：

  1. 文档分块 → Embedding → 存入向量库
  2. 查询 → Embedding → 相似度检索 → Top K → LLM生成

选型建议：

  • 快速验证 → Chroma（本地）/ Pinecone（云端）
  • 生产部署 → Milvus / Weaviate / pgvector
  • 中文场景 → bge / m3e 系列模型
