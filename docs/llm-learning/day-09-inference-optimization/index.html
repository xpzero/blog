Day 9：大模型推理优化

模型训练好后，真正的挑战是让它在生产环境跑起来。7B 模型 FP16 精度需要 14GB 显存，单张消费级显卡都装不下。这时候就得想办法压缩和加速。

我折腾了一周，把几种主流方案都试了一遍。记录一下过程和结果。

问题：显存不够​

LLaMA-2-7B 的显存占用：

精度显存需求单卡 4090 (24GB)
FP32~28GB❌ 装不下
FP16~14GB✅ 能装下
INT8~7GB✅ 很宽松
INT4~4GB✅ 还能跑更大的

FP16 虽然能跑，但 batch size 只能设 1。想要高并发或者跑更大的模型，必须量化。

方案一：INT8 量化​

原理​

把 FP16 的权重从 16bit 压缩到 8bit。精度损失约 1-2%，大部分场景感知不到。

实现​

用 bitsandbytes 库，两行代码搞定：

from transformers import AutoModelForCausalLM, BitsAndBytesConfig

quant_config = BitsAndBytesConfig(
    load_in_8bit=True,
    bnb_8bit_compute_dtype=torch.float16
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b",
    quantization_config=quant_config,
    device_map="auto"
)

效果​

  • 显存从 14GB 降到 7GB
  • 推理速度略降（约 10%）
  • 精度基本没感觉

坑​

device_map="auto" 在多卡时会拆分模型。单卡推理建议明确指定 device_map={"": 0}。

方案二：INT4 量化（GGUF）​

原理​

压缩到 4bit，配合分组量化减少精度损失。llama.cpp 的方案，现在用 ollama 或者 lmstudio 都能直接跑。

实现​

用 llama.cpp 的转换脚本：

# 下载模型后转换
python convert.py models/7B/

# 量化
./quantize models/7B/ggml-model-f16.bin models/7B/ggml-model-q4_0.bin q4_0

或者用现成的 GGUF 文件，HuggingFace 上很多。

效果​

  • 显存只要 4GB
  • 7B 模型在 MacBook M1 上能跑
  • 精度损失约 5-10%，简单对话够用，复杂推理有点糊

对比​

量化类型显存速度质量
Q4_04GB快一般
Q4_K_M4.5GB快较好
Q5_K_M5GB快好
Q6_K6GB快接近 FP16

我最后选了 Q5_K_M，质量和速度的平衡点。

方案三：KV Cache 优化​

问题​

推理时，模型需要缓存之前的 Key 和 Value。序列一长，这部分占用爆炸。

解决​

MQA（多查询注意力）：所有头共享同一组 K/V。

GQA（分组查询注意力）：几个头共享一组 K/V。

LLaMA-2 已经用 GQA 了，但还可以进一步优化缓存策略：

# 限制 KV Cache 大小
past_key_values = None
max_cache_len = 2048

for token in generate_tokens():
    outputs = model(..., past_key_values=past_key_values)
    past_key_values = outputs.past_key_values
    
    # 只保留最近的部分
    if past_key_values[0][0].shape[2] > max_cache_len:
        past_key_values = [
            (k[:, :, -max_cache_len:, :], v[:, :, -max_cache_len:, :])
            for k, v in past_key_values
        ]

效果​

长文本推理时，显存占用稳定，不会随序列长度线性增长。

最终配置​

我现在的部署方案：

from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

# INT8 量化 + 优化缓存
quant_config = BitsAndBytesConfig(
    load_in_8bit=True,
    llm_int8_threshold=6.0,
    llm_int8_has_fp16_weight=False
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-chat-hf",
    quantization_config=quant_config,
    torch_dtype=torch.float16,
    device_map={"": 0}
)

# 开启梯度检查点（推理时节省显存）
model.gradient_checkpointing_enable()

单卡 4090，batch size 能到 4，延迟 200ms 以内。

踩过的坑​

  1. 量化后模型变懒：INT4 的 Q4_0 格式，模型回答明显变短。换成 Q5_K_M 解决。

  2. 多卡比单卡慢：device_map="auto" 拆分模型，卡间通信 overhead 很大。单卡能装下的话，别用多卡。

  3. 温度参数要调：量化后的模型，温度设 0.7 容易重复。降到 0.5 效果好很多。

选型建议​

场景推荐方案
本地开发INT4 GGUF，省显存
生产部署INT8，平衡质量和速度
高并发服务vLLM + INT8，PagedAttention 优化
边缘设备INT4 + MLC LLM，手机都能跑

下一步试试 vLLM，据说吞吐量能提升 10 倍。
