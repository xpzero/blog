Day 9：大模型推理优化

训练完模型只是开始，怎么让它跑得快、吃得少，才是真正的工程活。今天聊推理优化。

推理的痛点​

内存​

LLaMA-2-70B 的显存需求：

精度显存
FP16140 GB
INT870 GB
INT435 GB

单卡 A100 才 80GB，FP16 根本跑不动。

速度​

自回归生成每次只能输出一个 Token。序列一长，KV Cache 膨胀，速度断崖式下跌。

KV Cache 管理​

是什么​

Transformer 推理时，前面算过的 K、V 可以缓存，不用重复算。

第 1 步：算 Token 1 的 K1, V1
第 2 步：用 K1,V1 + Token 2 算 → 输出 Token 2
第 3 步：用 K1,V1,K2,V2 + Token 3 算 → 输出 Token 3
...

KV Cache 存的就是这些历史 K、V。

问题​

Cache 随序列长度线性增长。长对话场景，Cache 可能比模型权重还占内存。

优化方案​

分页管理（PagedAttention）

vLLM 的做法：把 KV Cache 分页，非连续存储，按需分配。

压缩/淘汰

  • 滑动窗口：只保留最近 N 个 Token
  • 重要性筛选：丢掉不重要的 Token
  • H2O：保留 Heavy Hitters（高频访问的 Token）

MQA/GQA

昨天讲的，减少 KV Cache 的 heads 倍。

量化技术​

为什么能量化​

模型权重分布集中，大部分值在 -1~1 之间。用低精度表示，损失不大。

训练后量化（PTQ）​

INT8

scale = max(abs(W)) / 127
W_int8 = round(W / scale)
W_dequant = W_int8 * scale

问题：异常值（outliers）会把 scale 拉大，导致精度损失。

LLM.int8()：把 outliers 保留 FP16，其他转 INT8。

INT4/GPTQ​

INT8 还是太大，继续压到 4bit。

GPTQ（基于 OBS 算法）：

  • 逐层量化
  • 用 Hessian 矩阵补偿误差
  • 一次性处理，无需反向传播

效果：LLaMA-65B 从 130GB 压到 35GB，精度损失 < 1%。

AWQ​

Activation-aware Weight Quantization：

  • 观察激活值，保护重要权重
  • 比 GPTQ 更快、精度更好
  • 4bit 量化几乎无损

对比​

方法精度速度适用场景
FP16100%基准训练、高精度需求
INT8~99%1.5-2x通用推理
GPTQ-4bit~98%2-3x单卡大模型
AWQ-4bit~99%2-3x推荐首选

推理框架​

vLLM​

核心：PagedAttention + Continuous Batching

  • PagedAttention：解决 KV Cache 内存碎片
  • Continuous Batching：动态批处理，提高吞吐

适用：高并发服务场景

from vllm import LLM, SamplingParams

llm = LLM(model="meta-llama/Llama-2-7b")
outputs = llm.generate(prompts, SamplingParams(temperature=0.7))

TensorRT-LLM​

NVIDIA 出品，针对自家 GPU 深度优化。

  • Kernel 融合
  • FP8 支持（H100）
  • 多 GPU 并行

适用：生产环境、NVIDIA 显卡

llama.cpp​

C++ 实现，主打本地 CPU 推理。

  • GGUF 格式（量化 + 优化）
  • 支持各种量化级别（Q4_0、Q5_K_M、Q8_0）
  • 跨平台（Mac、Windows、Linux、手机）

适用：本地部署、边缘设备

./main -m llama-2-7b.Q4_K_M.gguf -p "你好"

选型建议​

场景推荐框架
服务端高并发vLLM
NVIDIA GPU 生产环境TensorRT-LLM
本地 CPU/Macllama.cpp
快速验证transformers

其他优化​

投机采样（Speculative Decoding）

用小模型快速生成候选 Token，大模型验证。正确就接受，错误就重采。2-3 倍加速，输出结果和原模型一致。

并行解码

  • Beam Search：多候选并行
  • Lookahead Decoding：提前计算多个位置

实践建议​

  1. 先量化再优化，4bit 量化是最有效的降本手段
  2. 选对框架：vLLM 适合服务，llama.cpp 适合本地
  3. 监控 KV Cache，长对话注意内存泄漏
  4. 能批则批，吞吐提升明显

总结​

推理优化的核心就三点：省内存（量化 + MQA/GQA）、提速度（Flash Attention + 高效框架）、保质量（AWQ/GPTQ 损失可控）。

明天开始聊微调，LoRA、QLoRA 这些。
