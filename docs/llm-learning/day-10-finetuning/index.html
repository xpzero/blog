Day 10：微调

现在大模型已经很强了，为什么还要微调？

因为通用模型不一定适合你的场景。

什么是微调？​

微调（Fine-tuning）是在预训练模型的基础上，用特定数据再训练一下。

让通用模型变成专用模型。

预训练模型（通才）→ 微调 → 专用模型（专才）

比如：

  • 通才：会写各种代码
  • 微调后：专门会写 Python 数据分析代码

什么时候用微调？​

  • 需要特定风格（回复语气、格式）
  • 需要特定领域知识（医学、法律）
  • 需要特定任务（客服对话、情感分析）
  • Prompt 工程不够用的时候

微调方法​

全参数微调​

更新模型所有参数。

效果好，但：

  • 成本高（需要多卡 GPU）
  • 容易过拟合（学过头）
  • 灾难性遗忘（忘了原来的能力）

LoRA​

Low-Rank Adaptation。

不更新所有参数，只更新一小部分。

原理：

  • 把大矩阵分解成两个小矩阵
  • 只训练这两个小矩阵
  • 原来的参数不动

效果：

  • 显存省 70-90%
  • 训练快
  • 不容易过拟合

现在最流行的微调方法。

QLoRA​

量化 + LoRA。

先量化模型（4-bit），再用 LoRA 微调。

更省显存，可以单卡微调大模型。

微调流程​

  1. 准备数据

    • 收集相关数据
    • 清洗（去噪音、补缺失）
    • 格式化成指令格式

  2. 训练配置

    • 学习率（小一点）
    • 批次大小
    • 训练轮数

  3. 训练

    • 监控 loss
    • 防止过拟合

  4. 评估

    • 效果是不是变好了
    • 能力有没有下降

数据格式​

常用格式：

{
  "instruction": "把这句话翻译成英文",
  "input": "你好，世界",
  "output": "Hello, world"
}

或者对话格式：

{
  "messages": [
    {"role": "user", "content": "翻译：你好"},
    {"role": "assistant", "content": "Hello"}
  ]
}

踩坑记录​

坑1：数据质量比数量重要 100 条高质量数据可能比 10000 条噪音数据效果好。

坑2：学习率要小 比预训练小 10-100 倍，不然容易崩。

坑3：评估不能只看 loss Loss 低不等于效果好。要看实际任务表现。

坑4：会丢失原有能力 微调后模型可能在某些方面变差。要评估是否在可接受范围。

什么时候选微调？​

方案适用场景
Prompt 工程效果够用，数据少
RAG需要外部知识
微调需要特定风格/领域，数据多

总结​

  • 微调让通用模型变成专用模型
  • LoRA/QLoRA 是主流方法，省显存效果好
  • 数据质量比数量重要
  • 不是所有场景都需要微调

这个系列到此结束。

学了这些，你应该理解了大模型是怎么认识文字、处理文字、生成回答的。

也知道怎么用 Prompt、RAG、Agent 这些工具放大模型的能力。

下一步可以继续深入某个方向，或者直接动手做项目。

祝学习愉快。
