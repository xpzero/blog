Day 4：Attention

昨天说 Transformer 的核心是 Self-Attention。但具体怎么"注意"，我没说清楚。今天补上。

Attention 在做什么？​

Attention 的本质是：加权求和。

每个词要看其他所有词，根据相关性决定给多少权重。

相关性高的词，权重就大。

Q、K、V 是什么？​

每个输入向量会生成三个向量：

  • Q（Query）：我想查询什么
  • K（Key）：我有什么
  • V（Value）：我的实际内容

计算方式：

Attention(Q, K, V) = softmax(Q × K^T / √d) × V

步骤：

  1. Q 和 K 做点积，算相关度
  2. 除以 √d 防数值过大
  3. softmax 变概率分布
  4. 乘 V 得加权结果

直观例子​

句子："那只猫很可爱，它喜欢睡觉"

问："它"和哪个词最相关？

  • "它"的 Q 和"猫"的 K 点积高 → 权重高
  • "它"的 Q 和"睡觉"的 K 点积也可能高 → 权重也高

所以"它"的表示 = 猫的信息 + 睡觉的信息。

这就是"注意"到上下文。

Multi-Head Attention​

一组 Q、K、V 叫一个"头"。

多组 Q、K、V 就是 Multi-Head Attention：

Head 1: 关注语法关系（主谓宾）
Head 2: 关注指代关系（它指谁）
Head 3: 关注语义相似（同义词）
...

最后把各头结果拼起来，再线性变换。

Attention 的问题​

标准 Attention 复杂度是 O(n²)：

n = 序列长度
计算量 = n × n（每个位置看每个位置）
  • n=512：512 × 512 = 26万次
  • n=4096：4096 × 4096 = 1677万次

内存和计算都爆炸。

优化方案​

1. 稀疏注意力 不看完所有，只看局部和部分重要位置。

2. Flash Attention 把计算从 HBM（显存）搬到 SRAM（缓存），减少读写。

3. MQA / GQA 多 Query 共享 K、V，大幅减少 KV Cache。

MQA：所有 Q 共享一组 K、V GQA：几组 Q 共享一组 K、V

LLaMA 2 用的是 GQA。

踩坑记录​

坑1：Attention 不是 Transformer 发明的 Attention 机制 2014 年就有了，用于机器翻译。Transformer 2017 年才提出，用了 Self-Attention + Multi-Head Attention。

坑2：不是所有 Attention 都一样 不同任务关注点不同。翻译任务更关注对应词，生成任务更关注前文。

坑3：可视化 Attention 不是因果关系 看到热力图说"这个词注意了那个词"，不代表真的有因果关系。有时候是噪声。

总结​

  • Attention 本质是加权求和
  • Q、K、V 分别负责查询、匹配、取值
  • Multi-Head 用多组关注不同方面
  • 标准 Attention 是 O(n²)，有各种优化
