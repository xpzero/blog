Attention

Transformer 需要让一段输入里的位置互相交换信息。处理"小王把书放在桌上，因为它太重了"这类句子时，模型要决定"它"与哪些前文内容相关。Attention 是其中用来为上下文分配不同关注程度的机制。

用一张表理解结果​

可以把某个位置读取前文信息的结果抽象成权重表：

前文片段当前步骤分配的权重
小王较低
书较高
桌上较低

模型会按这些权重合并前文携带的信息，得到当前位置的新表示。权重是模型内部计算结果，不是人工写下的语法规则，也不能单独证明模型的推理原因。

Q、K、V 的直观角色​

实现中，每个位置会派生出 Query、Key 和 Value 三类表示：

  • Query 表示当前位置要寻找什么信息。
  • Key 表示一个位置可被匹配的特征。
  • Value 是匹配后要带走的信息。

Query 和各个 Key 的匹配结果会被归一化为权重，再用于组合 Value。这是理解机制的简化模型，实际模型会在多层、多头中重复这个过程。

多头意味着什么​

Multi-Head Attention 会并行使用多组表示，再合并结果。论文中的设计目的是让模型能从不同表示子空间关注信息。不要把某个头固定解释成"专门负责语法"或"专门负责指代"，这种对应关系并不稳定。

对应用的影响​

标准全注意力需要比较序列中许多位置，输入变长时计算和显存压力会明显上升。服务端可能采用局部注意力、分组查询注意力或更高效的内核实现来缓解问题，但它们的支持范围和效果依赖具体模型。

对调用方而言，更稳妥的做法是控制无关上下文，测量真实请求的延迟和失败情况，而不是假定长窗口一定能稳定利用全部内容。
