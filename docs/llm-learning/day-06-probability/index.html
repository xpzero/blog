Day 6：概率与采样

大模型怎么"说话"的？每次输出一个词，它是随机选的还是怎么选的？

概率分布​

Transformer 输出是一个概率分布。

每个可能的下一个 Token，都有一个概率。

比如输入"今天天气"：

下一个词的概率：
- "很好" → 35%
- "不错" → 25%
- "糟糕" → 15%
- "晴朗" → 10%
- ...
（加起来 = 100%）

模型给每个词打分（概率），然后按概率采样。

这就是它"说话"的基本原理。

采样​

按概率随机挑一个词出来。

概率高的词，被选中的机会更大，但不一定每次都选中。

这就是为什么同一个问题，模型每次回答不完全一样。

温度（Temperature）​

温度控制"随机性"。

温度效果用在哪
0.0-0.3保守、确定写代码、算数
0.4-0.7平衡日常对话、翻译
0.8-1.2有创意、多样写作、头脑风暴
1.5+随机、可能乱说一般不用

低温（0.2）：

问：春天是什么感觉？
答：春天是温暖的季节，花开了。
（每次差不多）

高温（1.0）：

答1：春风拂面，桃花盛开
答2：冰雪消融，溪流潺潺
答3：燕子归来，万物复苏
（每次不一样，更有创意）

Top-p 和 Top-k​

Top-k：只从概率最高的 k 个词里选

Top-p：从概率累计达到 p% 的词里选

通常一起用：top_k=50, top_p=0.95

比如 top_k=5：
概率最高的 5 个词里选一个

比如 top_p=0.9：
从概率加起来达到 90% 的词里选

场景选择​

场景温度其他参数
写代码0.0-0.3低温度，更准确
事实问答0.0-0.3不要随机
创意写作0.7-0.9可以多样
头脑风暴0.9-1.0越随机越有创意

采样可能带来的问题​

有时候模型会"乱说"：

  • 低概率的词也可能被选中
  • 高温下更容易出现语法正确但意思奇怪的句子
  • 事实可能和正确答案不符

这叫"幻觉"（Hallucination）。

怎么控制幻觉？​

  1. 降低温度：牺牲创意换准确性
  2. Few-shot：给例子，让模型按例子走
  3. Prompt 约束：告诉模型"如果不确定，说不知道"

踩坑记录​

坑1：温度不是全局的 有的 API 对 system prompt 和 user prompt 用不同温度，注意配置。

坑2：top_k 和 top_p 会互相影响 两个都设的时候，模型会同时遵守两个约束。设太多限制可能让输出变差。

坑3：采样不等于"每次随机" 概率分布决定了随机性。如果 top_k=1，就变成了贪婪采样（总是选最高的），没有随机性了。

总结​

  • 模型输出是概率分布
  • 按概率采样决定选哪个词
  • 温度控制随机性：低温确定，高温创意
  • Top-k/p 控制候选范围
  • 高随机性带来更多创意，也更容易出错

明天聊 Prompt 工程，怎么问才能让模型答得好。
