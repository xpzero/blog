Day 9：Agent

RAG 让大模型能回答问题。但它只能"答"，不能"做"。

我想让大模型帮我干活：自动搜索、填表、发邮件、跑代码。

靠 Agent。

Agent 是什么？​

Agent（智能体）是能自主行动的大模型应用。

它不只是回答问题，而是：

  1. 理解目标
  2. 规划步骤
  3. 调用工具
  4. 观察结果
  5. 决定下一步

像一个助手，交代一件事，它自己去完成。

Agent 和普通大模型的区别​

普通大模型Agent
回答✅✅
搜索❌✅
执行代码❌✅
操作软件❌✅
多步骤任务一次完成分步完成

Agent 的核心组件​

1. 规划（Planning）​

把大目标拆成小步骤。

比如："帮我分析竞品"

拆成：

  1. 搜索竞品信息
  2. 提取关键数据
  3. 生成对比表格
  4. 写成报告

2. 工具（Tools）​

Agent 能调用各种工具：

  • 搜索（Google、Bing）
  • 代码执行（Python、Shell）
  • 文件操作（读、写、删）
  • API 调用（发邮件、查天气）
  • 浏览器操作（点击、填表）

3. 记忆（Memory）​

  • 短期记忆：当前对话的上下文
  • 长期记忆：之前任务的经验、知识

4. 工具调用（Tool Use）​

Agent 通过 Function Calling 或 MCP 调用外部工具。

让模型生成结构化的工具调用，而不是随便说。

常见 Agent 框架​

框架特点
LangChain功能全，但复杂
AutoGPT自主规划，强
Claude Code编程专用
OpenCode开源，编程专用

Agent 能做什么？​

  • 自动化工作流：自动处理重复任务
  • 研究代理：自动搜索、总结、写报告
  • 编程助手：自动写代码、调试、Code Review
  • 个人助理：自动发邮件、整理文件、管日程

Agent 的问题​

Agent 不是完美的：

  • 规划可能出错：拆的步骤不对，最后做不成
  • 工具调用可能失败：API 超时、权限问题
  • 自我纠错有限：错了不一定知道
  • 成本高：多步调用比单次贵很多

怎么用好 Agent？​

  1. 任务别太复杂：先从简单任务开始
  2. 给清楚的工具：让 Agent 知道有哪些工具可以用
  3. 监控执行：看着它做，发现问题及时干预
  4. 限制步数：避免无限循环

踩坑记录​

坑1：Agent 会陷入死循环 如果任务太复杂或者反馈不够清晰，Agent 可能一直重复某个步骤。设步数限制。

坑2：不是所有任务都适合 Agent 简单的一次性任务，直接问大模型就行，不用 Agent。

坑3：工具返回不一定有用 Agent 调用工具后，返回的结果可能不完整或者有噪声。需要处理。

总结​

  • Agent = 能自主行动的大模型应用
  • 核心：规划 + 工具 + 记忆 + 工具调用
  • 比普通大模型多了"做"的能力
  • 可以自动化多步骤任务

明天聊微调，怎么训练自己的大模型。
