Day 1：Token 是什么？

刚开始接触大模型的时候，我以为它跟人类一样，一个字一个字地读。后来发现完全不是这么回事——它用的是 Token。

一句话理解​

Token 是大模型处理文本的最小单位。中文里一个字可能拆成 1-2 个 Token，英文一个单词通常就是 1 个 Token。

Token 到底是什么？​

打个比方：

  • 人类阅读：以"字"和"词"为单位
  • 模型处理：以"Token"为单位
  • 就像拼图：人类看整体图案，模型看每一块拼图

Token 可以是：

  • 一个单词（"hello"）
  • 一个字（"你"）
  • 一个词的一部分（"unhappiness" → "un" + "happ" + "iness"）

为什么中文更"费"Token？​

文本Token 数说明
"Hello"1常见单词直接对应
"unhappiness"3拆成 "un" + "happ" + "iness"
"你好"2每个汉字 1-2 个 Token
"机器学习"4比英文同义词更耗 Token
"今天天气很好"6-8中文没有空格，需要更细切分

原因： 英文有空格分隔，中文需要模型自己切分，粒度更细。同样的意思，中文通常需要更多 Token。

Token 怎么影响使用？​

1. API 费用​

计费公式：

费用 = (输入 Token + 输出 Token) × 单价

实际案例：

  • 发送 1000 字中文报告（约 1500 Token）
  • 模型回复 500 字（约 750 Token）
  • GPT-4 价格：$0.03/1K Token
  • 费用 = 2250 / 1000 × $0.03 = $0.0675（约 0.5 元人民币）

同样的内容，中文通常比英文贵 1-2 倍。

2. 上下文限制​

模型有最大 Token 限制，超过就被截断：

模型上限约等于适用场景
GPT-3.54K-16K3-12 页文档简单对话
GPT-4128K约 100 页文档长文档分析
Claude 3200K约 150 页超长文档

常见问题：

  • 为什么长文档传不进去？→ 超过上下文窗口
  • 为什么聊久了模型"忘记"设定？→ 早期内容被挤出窗口

动手试试​

  1. 打开 OpenAI Tokenizer
  2. 输入以下内容，观察 Token 数：
文本Token 数观察
"Hello world"2英文短句
"你好世界"4中文短句
"Machine learning is fascinating"5长英文
"机器学习非常有趣"8长中文

思考： 同样的意思，中英文 Token 数差异大吗？

省钱技巧​

1. 精简提示词​

低效（20 tokens）：

请帮我分析一下下面这段文字的内容和含义

高效（4 tokens）：

分析：

2. 能用英文就用英文​

特别是技术文档、代码相关的内容，英文更省 Token。

3. 控制输出长度​

设置 max_tokens 限制回复长度，避免意外超长回复。

4. 分段处理长文档​

超过上下文限制的文档，分段发送，分别处理。

今日总结​

核心概念：

  • Token 是模型的"文字积木"
  • 中英文 Token 效率不同（中文更"费"）
  • Token 数量影响 API 成本和上下文限制

实用技巧：

  • 精简提示词，去掉废话
  • 技术内容优先用英文
  • 控制输出长度
  • 长文档分段处理
