Token 与分词

LLM 已经进入编码、搜索和自动化工作流。想判断一次调用为什么收费、长文为什么会失败，先从人类文本进入模型的第一层开始：模型并不直接按"字"或"单词"读取输入，它读取的是 Token。

先观察一次切分​

可以在 OpenAI Tokenizer 中输入一段自己的文本，查看工具显示的 Token 边界和总数。这个结果只代表该工具所选分词器；换一个模型或版本，结果可能不同。

例如，把带空格的英文和没有空格的中文分别输入，通常能看到切分边界并不等于自然语言中的词边界。代码里的空格、标点和换行也会参与切分。

Token 是什么​

Token 是模型处理文本的一段编码单位。分词器先把文本切成 Token，再把每个 Token 转成数字 ID，模型才接收这些 ID。

原文 -> 分词器 -> Token ID 序列 -> 模型

Token 可能是一个字、一个完整单词、词的一部分，或者标点和空白。具体边界由分词器的词表和规则决定，不能用"一个中文字符等于一个 Token"这样的固定换算。

为什么开发时要关心它​

  • 接口通常按输入和输出 Token 统计用量，计费方式以服务商文档为准。
  • 模型能同时处理的输入和输出总量受上下文窗口限制。
  • 日志、HTML、JSON 和重复的提示词都会占用 Token。

一个实用做法是在请求前统计或估算 Token 数，在请求失败时记录输入长度和模型返回的限制信息。不要只按字符数截断长文本，否则可能在 Token 层面仍然超限。

分词器并不通用​

常见的子词分词方法包括 BPE、WordPiece 和 SentencePiece。它们训练出的词表不同，因此同一段文本在不同模型上的 Token 数可以不同。

如果应用调用的是某个具体模型，应使用该模型提供或明确兼容的分词器做本地估算。在线 Tokenizer 适合观察，不应代替生产请求中的实际限制检查。

容易忽略的问题​

  • 不要把某个模型的 Token 数套用到另一个模型。
  • 输入预算要留给模型输出和系统提示词，不能只计算用户文本。
  • 压缩文本可能损失约束、字段名或代码结构；先删重复内容，再考虑摘要或分段。
